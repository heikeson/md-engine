This file is the **single source of truth** for the engine/host interface. The implementation may change; signatures and behaviour may not. Anything marked "grow only" is a breaking change if violated once.

## 0. Quick reference

| Host need | Use | See |
|---|---|---|
| Render an article | `<MarkdownRenderer content />` | §5 |
| Get structure / TOC / positions | `parse(md)`; diagnostics only: `diagnose(md)` | §4 |
| Store back as Markdown | `serialize(tree)`, `roundtrip(md)` | §6 |
| Authoring UI | `<MarkdownEditor value onChange />` | §7 |
| Change language site-wide | `MdEngineProvider` at the root, or `config.locale` | §8 |
| Re-theme | Override `--lkes-*` variables | §10 |
| Interactive diagrams | `mermaidComponents` from `/mermaid` | §11 |

## 1. Three contract constraints

| # | Constraint | Meaning | Violation counts as |
|---|---|---|---|
| C1 | Content syntax grows only | Components are added only; never renamed, removed, re-typed, or given new child names | Historical posts break |
| C2 | Config API grows only | New options must ship a default; existing fields are never removed or re-typed | Host fails to compile or changes behaviour on upgrade |
| C3 | Styles ship with the package | Component styles come from the package; hosts override CSS variables only | Styles vanish if the host misses a rebuild |

The host explicitly **does no content migration**, so C1 is non-negotiable: this package must not ship a breaking change. C2 covers render config, editor config, `UIText` message keys and diagnostic codes; C3 covers `--lkes-*` variables and package class names.

**Module format**: ESM-only. `exports` declares `import` conditions only, no `require`; CommonJS consumers need their own bundling or interop layer. Adding a CJS entry is a compatibility decision reserved for the repository owner.

**Stability tiers**: the names and signatures listed in §3–§8, §10 and §11 are contract. Low-level helpers such as `jsxBlocks`, `jsxFromMarkdown` and `extractBlocks` are usable by hosts, but only "will not be removed" is promised — their exact signatures are not.

## 3. registry

The single source of truth for syntax. Parsing, serialization and the editor block UI all read it; component and attribute names must not be hardcoded anywhere else.

```ts
export type ComponentMode = "visual" | "source";

export interface ComponentSpec {
  /** Component name, capitalised, case-sensitive */
  readonly name: string;
  /** visual: structured editing; source: handled as a source block only */
  readonly mode: ComponentMode;
  /** Child component name; a single string, or an array when kinds are mixed (Files → ["Folder","File"]) */
  readonly items?: string | readonly string[];
  /** Allowed string attributes */
  readonly attrs?: readonly string[];
  /** Allowed boolean attributes (bare, no value) */
  readonly boolAttrs?: readonly string[];
  /** Leaf component, self-closing allowed (e.g. `<Image />`) */
  readonly selfClosing?: boolean;
  /** Attribute defaults */
  readonly defaultAttrs?: Readonly<Record<string, string | boolean>>;
  /** Container body is raw text (not parsed as Markdown); default false */
  readonly rawBody?: boolean;
}

export interface ItemSpec {
  readonly name: string;
  readonly attrs?: readonly string[];
  readonly boolAttrs?: readonly string[];
  readonly selfClosing?: boolean;
}

/** Max container nesting depth (containers only; child items do not count) */
export const MAX_CONTAINER_DEPTH = 3;

export const COMPONENTS: Readonly<Record<string, ComponentSpec>>;
export const ITEMS: Readonly<Record<string, ItemSpec>>;

export function getComponent(name: string): ComponentSpec | undefined;
export function getItemSpec(name: string): ItemSpec | undefined;
/** Every container name, for editor menus and validation */
export function listComponents(): string[];
export function isContainerWithItems(name: string): boolean;
```

### 3.1 Containers

| name | mode | items | Attributes | Notes |
|---|---|---|---|---|
| `Callout` | visual | — | `type` (default `note`), `title`, `icon` | Body is still Markdown; `icon` as emoji/short text replaces the default icon |
| `Tabs` | visual | `Tab` | — | ←/→/Home/End keyboard switching, WAI-ARIA |
| `Steps` | visual | `Step` | — | Ordered steps |
| `Cards` | visual | `Card` | — | Card links |
| `Accordion` | visual | `AccItem` | — | Optional default-expanded item |
| `Files` | visual | `Folder`, `File` | — | Mixed children allowed |
| `TypeTable` | visual | `TypeItem` | — | Header labels come from `UIText` |
| `Columns` | visual | `Column` | — | Horizontal columns; stacks into one column below 640px |
| `Timeline` | visual | `TimelineItem` | — | Vertical timeline, marker colour follows the item `type` |
| `Video` | visual | — | `src`, `poster`, `caption`, `width` | Self-closing; `src` / `poster` go through the same protocol allow-list as `Image` |
| `Image` | visual | — | `src`, `alt`, `align` (default `center`), `width`, `caption`, boolean `zoom` | Self-closing; `zoom` enables click-to-enlarge |
| `div` | visual | — | `class`, `id` | Attributes pass through to the DOM, no wrapper component; body parsed as Markdown |
| `Mermaid` | source | — | `title`, `height` | `rawBody` + self-closing; body is **raw text** |

### 3.2 Child items

| name | Attributes | Boolean attributes | Self-closing | Notes |
|---|---|---|---|---|
| `Tab` | `value` | `default` | — | Label comes from the body |
| `Step` | `title` | — | — | Step title |
| `Card` | `title`, `href`, `icon`, `description` | — | yes | Description may be an attribute or the body |
| `AccItem` | `title`, `type` (`open` / `close`) | — | — | `#id` deep-link match wins over `type` |
| `Folder` | `name` | `defaultOpen` | — | File-tree directory |
| `File` | `name`, `href`, `icon` | — | yes | Renders as a link when `href` is given |
| `TypeItem` | `name`, `type`, `default` | `required` | yes | Description column via body or left empty |
| `Column` | `width` | — | — | Bare number splits by ratio, value with unit sets a fixed width; omitted means equal split |
| `TimelineItem` | `date`, `title`, `type` (`note` / `tip` / `warning` / `danger`) | — | — | Unknown `type` renders as `note` |

Rules:

1. Names are **case-sensitive**; `Tab` and `tab` are different names.
2. Attribute values are strings only; boolean attributes must be bare (`default`, `zoom`). `{...}` expressions are unsupported — such an open tag falls back to plain HTML/text, producing no container and no error.
3. Child items only carry meaning inside their container. A top-level `<Tab>` still parses as a block, but it is not in `listComponents()`, so the editor shows no container UI.
4. Adding a component means editing `registry` plus shipping the implementation and docs; declarations only grow.

## 4. parse

```ts
export interface ParseOptions {
  /** Override the nesting limit; defaults to MAX_CONTAINER_DEPTH */
  maxDepth?: number;
  /**
   * Extract the flat block index, default true
   * @description When false, extractBlocks is skipped and `ParseResult.blocks` is an empty array;
   *   diagnostics, serialization and rendering are unaffected
   */
  blocks?: boolean;
}

export interface ParseResult {
  tree: Root;                 // mdast with containers as custom nodes
  blocks: Block[];            // flat block index, in document order
  diagnostics: Diagnostic[];
}

export function parse(md: string, options?: ParseOptions): ParseResult;

/** Diagnostics only: equivalent to `parse(md, { blocks: false }).diagnostics` */
export function diagnose(md: string, options?: ParseOptions): Diagnostic[];
```

`parse` only parses and diagnoses: it never rewrites the source, adds blank lines or touches indentation. `null` / `undefined` are treated as an empty string.

### 4.1 Block

```ts
export type SourceReason =
  | "html"           // raw HTML block
  | "definition"     // link definition
  | "unknown"        // tag outside the whitelist
  | "list-context"   // degraded inside a list context
  | "depth-exceeded" // nesting limit hit
  | "mermaid";       // rawBody container: source only, no structure

export type Attrs = Readonly<Record<string, string | boolean>>;

export interface VisualBlock {
  kind: "visual";
  /** mdast node type, e.g. heading / paragraph / table */
  type: string;
  start: number;
  end: number;
  /** list / listItem / blockquote only: inner blocks (how containers inside lists stay visible) */
  blocks?: Block[];
}

export interface SourceBlock {
  kind: "source";
  text: string;
  reason: SourceReason;
  start: number;
  end: number;
}

export interface ContainerItem {
  name: string;
  attrs: Attrs;
  blocks: Block[];
  start: number;
  end: number;
}

export interface ContainerBlock {
  kind: "container";
  name: string;
  attrs: Attrs;
  depth: number;      // starts at 1; child items do not count
  blocks: Block[];    // body of containers without items (Callout / Image / div)
  items: ContainerItem[]; // children of containers with items (Tabs / Steps / Cards / Accordion / Files / TypeTable)
  start: number;      // opening tag offset
  end: number;        // closing tag end offset
}

export type Block = VisualBlock | SourceBlock | ContainerBlock;
```

`blocks` is a read-only derivation: use it for TOCs, positioning and scroll sync; do not mutate it or cache it across parses.

### 4.2 Diagnostic

```ts
export type DiagnosticCode =
  | "UNCLOSED_TAG"
  | "DEPTH_EXCEEDED"
  | "UNKNOWN_TAG"
  | "UNSAFE_HREF"
  | "INDENT_AS_CODE"
  | "MERMAID_EMPTY"
  | "MERMAID_TOO_LARGE"
  | "DUPLICATE_ID_ANCHOR"
  | "DUPLICATE_ID_DIV"
  | "DUPLICATE_ID";       // @deprecated, no longer emitted since 0.5.0, still translatable

export interface Diagnostic {
  code: DiagnosticCode;
  level: "warn" | "error";   // every current diagnostic is "warn"
  line: number;              // 1-based
  message: string;           // Chinese fallback text
  params?: Record<string, string | number>;  // interpolation values
  range?: [number, number];  // full-text offset range
}
```

| Code | Trigger | Degradation |
|---|---|---|
| `UNCLOSED_TAG` | Container never closed before EOF | Renders as a container without swallowing content; serialization adds no closing tag |
| `DEPTH_EXCEEDED` | Nesting exceeds `maxDepth` | Node kept and marked `data.degraded`: rendered as a source block, serialized verbatim, indexed as `source` (`depth-exceeded`) |
| `UNKNOWN_TAG` | Capitalised tag outside the whitelist | Tag and body both shown as text (no HTML execution, nothing dropped) |
| `UNSAFE_HREF` | `href` / `src` / `poster` / `formaction` / `srcset` failed the scheme whitelist | Link not clickable (`href` → `#`), other attributes removed |
| `INDENT_AS_CODE` | Indented, unfenced content inside a container became a code block | Warning only; source untouched |
| `MERMAID_EMPTY` | Diagram source empty or whitespace | Source block plus a notice, never a blank area |
| `MERMAID_TOO_LARGE` | Diagram source above `MERMAID_MAX_BYTES` (20 KB) | No diagram; source shown verbatim, node marked `data.mermaidTooLarge` |
| `DUPLICATE_ID_ANCHOR` | `div id` collides with a heading anchor | Warning only; no rewriting |
| `DUPLICATE_ID_DIV` | Two `div id` values collide | Warning only; no rewriting |

`message` is the Chinese fallback for logs and provider-less contexts; UIs should localise by `code` (§8).

### 4.3 Position rules (hard requirements)

1. Every `start` / `end` is a **full-text offset** (0-based, `end` exclusive), directly usable as `source.slice(start, end)`.
2. A container's `start` is the first char of the opening tag; `end` is the last char of the closing tag plus one.
3. Offsets must be produced **natively by the tokenizer**; "rough parse, then re-parse fragments and accumulate offsets" is forbidden.
4. Regression check: `container nodes === opening tags in source`; any mismatch is an implementation defect (see §13 item 4).

### 4.4 Implementation requirement: a micromark extension

| Requirement | Detail |
|---|---|
| Syntax layer must be a micromark flow extension | `flow: { [60]: jsxBlock }` (`60` is `<`), `concrete: true`, body recurses through the standard Markdown flow |
| Do not assemble from html nodes | That falls back to CommonMark HTML-block rules: blank lines become hard boundaries again and an opening tag hugging a paragraph is swallowed by it |
| `nok` immediately when the name is not in registry | Control returns to the built-in html flow; `<section>` and friends behave as before |
| Closing matches by name, innermost first | Same-name nesting uses a name stack; unclosed at EOF degrades as "unclosed" without swallowing content |
| Reference implementation | `node_modules/micromark-extension-directive/lib/directive-container.js` |

Consequence: **blank lines are not required**. They only affect readability; the parse result is identical either way.

### 4.5 Parsing behaviour

| Input | Behaviour |
|---|---|
| `<Name>` and `</Name>` on their own lines | Normal container node (no blank line needed) |
| Opening tag hugging the previous paragraph | Normal container node (the flow construct can interrupt a paragraph) |
| No blank lines between tags | Parses normally (`concrete` body runs the standard Markdown flow) |
| Container on one line, `<Callout>text</Callout>` | Unsupported; treated as inline text (the opening tag must end its line) |
| Child item on one line, `<Tab value="a">A</Tab>` | **Supported**: folded into a structured item with props and content preserved (multi-paragraph form also works) |
| Blank line inside a child item | Supported: folded into one item across paragraphs |
| `</Name>` at line start | Ends that container; **the same holds inside fenced code (``` / ~~~)** |
| Unclosed | Renders as a container without swallowing content; serialization adds no closing tag; emits `UNCLOSED_TAG` |
| Opening tag spanning lines (`<Callout` then attributes) | Unsupported; shown as text |
| Inside a table cell or inline | Unsupported; shown as text (containers only trigger at line start) |
| Tag outside the whitelist (`<section>`, `<Foo>`) | Tag and body are **both** shown as text; capitalised names additionally emit `UNKNOWN_TAG`. `<div>` is registered |
| Nesting beyond the limit | Node kept and marked `data.degraded`; emits `DEPTH_EXCEEDED` |
| Body indented ≥4 spaces / a tab | Becomes a CommonMark code block (**not rewritten**) and emits `INDENT_AS_CODE`; a line of "indent + known tag" has its indent moved out of the body first and is then judged at column 0, so indented child items still work |
| Container inside a list item | Parses normally; exposed recursively through `VisualBlock.blocks` (list / blockquote / listItem) |
| Child item at top level (`<Tab>`, `<File>`, …) | Parses as a block, but without its container it carries no semantics and is absent from `listComponents()` |

### 4.6 GFM and math

Parsing and rendering share one extension set: GFM (tables, strikethrough, task lists), `$…$`, `$$…$$` and the angle-bracket blocks are registered side by side.

- A single-line `$$E=mc^2$$` is promoted to a **block formula** and serializes back as `$$`, never downgraded to `$…$`.
- Formula content is preserved verbatim; `_` and `\` are not escaped, so saving does not deform it.
- Hosts building their own toHast pipeline from `parse()` output must keep `data.hName` / `data.hChildren` (present on promoted math nodes) or formulas render empty.

## 5. render

```tsx
export interface RenderConfig {
  /** Per-component escape hatch; anything not overridden keeps the built-in implementation (key = container name, case-sensitive) */
  components?: Partial<Record<string, React.ComponentType<Record<string, unknown>>>>;
  /** Host remark plugins (run before mdast → hast) */
  remarkPlugins?: PluggableList;
  /** Host rehype plugins (must be synchronous to stay SSR safe) */
  rehypePlugins?: PluggableList;
  /** Emit data-src-start on block elements (editor scroll sync), default false */
  sourcePositions?: boolean;
  /** Per-key message overrides (wins over `text` and the built-in bundles) */
  messages?: UITextPatch;
  /** @deprecated Superseded by `messages`; `messages` wins when both are given */
  text?: UITextPatch;
  /** BCP-47 locale; falls back to an outer Provider, then zh-CN */
  locale?: string;
  /** Fallback locale when the target is not bundled, default zh-CN */
  fallbackLocale?: string;
}

export interface MarkdownRendererProps {
  content: string;
  /** Outer class name: container styles hang off the body class, so hosts normally pass one */
  className?: string;
  config?: RenderConfig;
}

export function MarkdownRenderer(props: MarkdownRendererProps): React.ReactElement;
```

Rules:

1. Attributes map to component props verbatim (attribute name = prop name, no camelCase conversion).
2. Every URL attribute passes one scheme whitelist: `http(s)`, `mailto`, `tel`, anchors, queries, relative and protocol-relative paths are allowed; any other scheme (including `data:` and `javascript:`) is rejected. A rejected `href` becomes `#`; `src` / `poster` / `formaction` are removed; `srcset` is validated per candidate and dropped entirely if any candidate fails; non-string values are treated as unsafe. Emits `UNSAFE_HREF`.
3. The gate sits in hast: even a host override of `a` / `img` never sees a dangerous address.
4. Component styles use package semantic classes only; never host Tailwind classes.
5. Custom plugins must be synchronous; plugin arrays are cached by reference and must be treated as immutable (in-place mutation will not invalidate the cache).
6. `sourcePositions` is for the editor only; leave it off on public pages.
7. Message resolution is described in §8; `MarkdownRenderer` wraps its output in its own `MdEngineProvider`, so `config.locale` applies to that layer.
8. Multiple instances on one page do not each build a pipeline: without host plugins two processors are shared globally (with / without `sourcePositions`).

## 6. serialize and format

```ts
/** mdast → Markdown; containers are emitted by their handler, shape preserved from the source */
export function serialize(tree: Root): string;

/** Convenience check: md → AST → md */
export function roundtrip(md: string): string;

/** Identity since 0.5.3: returns its input unchanged, kept for compatibility only */
export function normalizeMarkdown(md: string): string;
```

Guarantees:

1. **Lossless round trip**: `roundtrip(md)` equals the source, except for the engine's existing normalisations (`-` bullets, `*` emphasis, fenced code blocks, whitespace around table delimiters).
2. **Container shape preserved**: inline forms emit `<X a="b">content</X>`; block forms keep the source's line spacing — blank lines stay blank, tight lines stay tight; empty containers keep opening and closing tags on separate lines.
3. `serialize` never changes the number of blank lines: no adding, no collapsing.
4. **The engine does not format for you**: since 0.5.3 `normalizeMarkdown` returns its input unchanged (it does not even convert CRLF), and the editor never calls it. Implement formatting on the host side if you need it.

### 6.1 Shape and indentation

| Item | Owned by | Notes |
|---|---|---|
| Inline vs block shape | `serialize` | Decided at parse time; whatever the source wrote is written back |
| Blank lines | preserved by `serialize` | The engine never adds or removes them |
| Indentation | tolerated at parse time, never reflowed | "Indent + known tag" is recognised as a tag; indented prose is still a CommonMark code block |

## 7. editor

```tsx
export interface EditorConfig {

  uploadImage?: (file: File) => Promise<string>;
  /** Empty-document placeholder; takes precedence over `messages.editorPlaceholder` */
  placeholder?: string;
  /** Read-only */
  readOnly?: boolean;
  /** Preview render config (passed straight to MarkdownRenderer) */
  rendererConfig?: RenderConfig;
  /** Per-key message overrides (wins over `text` and the built-in bundles) */
  messages?: UITextPatch;
  /** @deprecated Superseded by `messages` */
  text?: UITextPatch;
  /** Locale; falls back to an outer Provider, then zh-CN */
  locale?: string;
  fallbackLocale?: string;
}

export type EditorView = "split" | "source" | "preview";

export interface MarkdownEditorProps {
  value: string;
  onChange: (value: string) => void;
  /** Initial view; afterwards the toolbar switches it */
  view?: EditorView;
  config?: EditorConfig;
  /** Fullscreen state owned by the host; the button only appears when passed */
  fullscreen?: boolean;
  onToggleFullscreen?: () => void;
}

export function MarkdownEditor(props: MarkdownEditorProps): React.ReactElement;
```

Rules:

1. `onChange` always hands back **exactly what the user typed**: no `normalizeMarkdown`, no added blank lines.
2. The editor only edits text; it never produces HTML.
3. Block property panels are generated from `registry`; forms are not hardcoded.
4. Diagnostics appear in the status bar: no dialogs, no blocked input.
5. `rendererConfig` is passed straight to the preview, and `sourcePositions` is forced on by the editor. To get interactive `<Mermaid>` charts in the built-in preview, pass `{ components: mermaidComponents }`; otherwise the source skeleton is shown. The editor entry does **not** depend on `/mermaid`.
6. Each input batch parses once: diagnostics and preview share a single `parse()`, and the preview goes through the internal `MarkdownTreeRenderer`. `useDeferredValue` keeps keystrokes responsive.
7. Split-view scroll sync uses **anchor interpolation**: block-level `data-src-start` markers form anchors (innermost only, stale fallbacks filtered out), the source side resolves the exact character position with `posAtCoords`, and adjacent anchors are interpolated linearly. Preview → source sets `scrollTop` via `lineBlockAt`. Nothing snaps to "top of nearest anchor".
8. Toolbar actions and keyboard shortcuts share plain functions and can be reused:

| Shortcut | Action |
|---|---|
| `Mod+B` / `Mod+I` / `Mod+E` | Bold / italic / inline code |
| `Mod+Shift+S` | Strikethrough |
| `Mod+1` | Heading 2 |
| `Mod+Shift+Q` | Blockquote |
| `Mod+Shift+L` | List |

`./editor` also exports `wrapSelection`, `toggleLinePrefix`, `insertBlockAt`, `insertAtCursor`, `blockSnippet` and `INSERTABLE_BLOCKS`, so custom toolbars need no copy of the logic.

## 8. Locale and messages

Fixed package strings (aria labels, chart toolbar, editor toolbar and status bar, type-table headers, diagnostics) live in `UIText`, Chinese by default.

**Resolution order** (per key; never a missing key):

```
config.messages (per-key override)
  → built-in bundle[locale]
  → built-in bundle[fallbackLocale]
  → zh-CN
```

| Option | Where | Notes |
|---|---|---|
| `locale` | `RenderConfig` / `EditorConfig` / `MdEngineProvider` | BCP-47; `zh_CN`, `en-us` are normalised |
| `fallbackLocale` | same | Defaults to `zh-CN` |
| `messages` | same | Per-key overrides, `UITextPatch` |
| `text` | same | `@deprecated`, equivalent to `messages`; `messages` wins when both are given |

```tsx
export interface MdEngineProviderProps {
  locale?: string;          // when omitted: outer Provider → storage → zh-CN
  fallbackLocale?: string;
  messages?: UITextPatch;   // layered over the outer provider, this layer wins
  storage?: LocaleStorage;  // defaults to localStorage + `lkes-md-lang`
  children?: ReactNode;
}

export function MdEngineProvider(props: MdEngineProviderProps): ReactNode;
export function useLocale(): { locale: string; direction: "ltr" | "rtl"; fallbackLocale: string };
export function useUIText(): UIText;
export function useMessage(): (key: keyof UIText, values?: Record<string, string | number>) => string;
```

Rules:

1. The library **never inspects the environment**: no `navigator`, no cookies, no `<html lang>`. `locale` must be a controlled value identical on server and client (route segment or request header), otherwise the first paint mismatches and hydration warns.
2. If you really need client detection, call `detectLocale(fallback?)` from an effect or event handler only.
3. `dir` belongs to the host: the engine only exposes `isRTL(locale)` and `useLocale().direction`; it never writes a `dir` attribute.
4. Messages use ICU MessageFormat, so `{n, plural, …}` works. On Node small-icu builds, check `supportsIntlLocale(locale)` first.
5. `Diagnostic.message` is a Chinese fallback; render localized text with `formatDiagnostic(t, diagnostic)` (it maps through `diagnosticTextKey`).
6. **Keys grow only**: `UIText` keys and their meaning fall under C2; removing or renaming one is a breaking change.
7. Locale helpers (`normalizeLocale`, `languageOf`, `localeCandidates`, `matchLocale`, `resolveLocale`, `toRouteSegment`, `fromRouteSegment`, `createLocaleStorage`, `BUILTIN_LOCALES`, `DEFAULT_LOCALE`) are pure functions and usable in host routing or middleware.

## 9. Host integration steps

1. Install: `npm install @heikeson/md-engine` (React 19+ required).
2. Add `@import "@heikeson/md-engine/styles.css";` to global styles; override §10 variables to re-theme. When importing slices, load `styles/tokens.css` first.
3. Replace public rendering:

```tsx
import { MarkdownRenderer } from "@heikeson/md-engine";

<MarkdownRenderer content={post.content} className="prose-site" config={{ locale }} />;
```

4. Replace admin editing (client component):

```tsx
import { MarkdownEditor } from "@heikeson/md-engine/editor";

<MarkdownEditor value={value} onChange={setValue} view="split" config={{ uploadImage }} />;
```

5. Site-wide locale (optional): wrap the root in `MdEngineProvider` and feed `locale` from the route segment or request header.
6. Persistence: store exactly what `onChange` gives you — **no** `normalizeMarkdown` call needed.
7. Diagrams (optional): merge `mermaidComponents` inside a client component (§11.4).
8. No `transpilePackages`, no Tailwind.

## 10. CSS variable contract

The namespace is `--lkes-*`: hosts may override, and the package must supply defaults. Nine base tokens:

`--lkes-bg` (surface), `--lkes-fg` (body text), `--lkes-muted` (secondary text), `--lkes-fill` (tinted fills: table head, code, row hover), `--lkes-border` (lines), `--lkes-accent` (emphasis: active underline, expander, card hover), `--lkes-ring` (focus ring), `--lkes-radius` (corners), `--lkes-overlay` (image zoom scrim).

**Both light and dark literals ship in the package**: light on `:root`, dark on a `.dark` / `[data-theme="dark"]` **ancestor** — add `.dark` to an ancestor and every component (editor shell included) switches at once.

Defaults **do not read host variables**: a `var()` inside a custom property is resolved where it is declared, so switching `.dark` later on the host has no effect — that is exactly why "some components stay light" used to happen.

Override by redeclaring the variable in normal (unlayered) CSS. `:root`, `.dark` or a body container all work, and import order does not matter (package defaults live in the `lkes.tokens` layer, which loses to unlayered declarations).

Class names never change with variables, so existing class-level overrides keep working. Callout's five state colors are semantic constants (plus the fumadocs aliases `warn` / `error` / `success` / `idea`); they do not use those tokens — override the `.callout-*` classes instead. Likewise `--lkes-tone` (the semantic hue used by Callout and Timeline) and `--lkes-col-grow` / `--lkes-col-basis` (Columns widths) are component-scope internals, not part of the nine tokens.

Chart colors are **not** here: `<Mermaid>` ships its own `--lkes-chart-*` set in the component's own scope, independent of host variables. See §11.9.

## 11. Mermaid diagram container

### 11.1 Syntax

```md
<Mermaid title="Request flow" height="480">
graph TD
  A[Start] --> B{Check}
  B -->|yes| C[Run]
</Mermaid>
```

| Attribute | Type | Default | Notes |
|---|---|---|---|
| `title` | string | none | Chart title, rendered as a caption |
| `height` | numeric string / `auto` | `auto` | Upper bound for the chart area (px). Omitted / empty / `auto` all mean automatic height: the area takes the initially fitted height, leaving no blank screen; a positive number becomes the viewport height and overflow is reached by panning |

### 11.2 Three hard rules

1. **The body is raw text**: no inline Markdown, no nested containers. `#`, `|`, `-->` and leading `-` survive verbatim.
2. **Only a line-start closing tag counts**: the body closes at a `</Mermaid>` at line start; the same text mid-line never truncates the chart.
3. **Must be written at column 0**: an opening tag indented ≥4 spaces becomes an indented code block.

`<Mermaid />` is allowed: it equals empty source, emits `MERMAID_EMPTY` and renders an empty source block.

### 11.3 Diagnostics

| Code | Trigger | Degradation |
|---|---|---|
| `MERMAID_EMPTY` | Body empty or whitespace | Source block plus a notice, never blank |
| `MERMAID_TOO_LARGE` | Source above 20 KB (`MERMAID_MAX_BYTES`) | No diagram; source shown verbatim; node marked `data.mermaidTooLarge` |

Both cases leave the source untouched: serialization still writes it back verbatim.

### 11.4 Host wiring

```tsx
// The host component must be a client component ("use client")
import { MarkdownRenderer, mdxComponents } from "@heikeson/md-engine";
import { mermaidComponents } from "@heikeson/md-engine/mermaid";
import "@heikeson/md-engine/styles.css";

const components = { ...mdxComponents, ...mermaidComponents };

<MarkdownRenderer content={md} config={{ components }} />;
```

- Without `mermaidComponents`, `<Mermaid>` stays a **source skeleton** (`figure` + `pre`) and mermaid is never loaded.
- The override key must be `Mermaid` with a capital M: the renderer looks it up by hast tagName, so lowercase fails silently and the skeleton stays.
- mermaid loads dynamically once a chart **enters the viewport**; one load per page; failures degrade to the source with a console warning.

### 11.5 Component props contract

| prop | Type | Notes |
|---|---|---|
| `raw` | `string?` | Diagram source |
| `code` | `string?` | Compatibility alias for `raw`; `raw` is used when omitted |
| `title` | `string?` | Caption |
| `height` | `string?` | Validated height bound |
| `tooLarge` | `boolean?` | Source over the limit; source shown only |

`mermaidComponents.Mermaid` and the main entry's `MermaidPlaceholder` share one signature (`MermaidProps`), so single-component overrides only need the fields above; remaining hast attributes pass through.

### 11.6 Interaction and export

**Initial view**: fitted to the container width (never above 1:1; container height also considered when `height` is given) and centred, so large diagrams are not cropped. The chart area has **no padding**: the canvas (the pannable/clipped viewport) shares edges with the card.

| Action | Behaviour |
|---|---|
| Left-drag | **The whole chart area drags** (the viewport is the gesture surface); it follows the pointer 1:1 regardless of zoom; presses on links, images or form controls are not captured |
| Dragging out of bounds | Allowed (one viewport of slack), then a 200 ms easeOut snap back to the nearest legal position on release; content smaller than the viewport can sit anywhere without snapping to centre; movement ≤ 5 px counts as a click and does not snap |
| Two-finger pinch (touch) | Scales around the midpoint of both fingers, which also drags when it moves; lifting one finger ends the pinch, and out-of-bounds cases snap back without flinging the chart |
| One-finger swipe (touch) | Horizontal gestures pan the chart, **vertical gestures scroll the page** (`touch-action: pan-y`) |
| Text | Text is selectable when idle; selection is locked only while dragging |
| Wheel | Not intercepted by default; the page scrolls normally |
| Left-drag + wheel / Ctrl (⌘) + wheel | Zooms around the cursor (multiplicative, clamped to 0.75–1.33 per step), keeping the point under the pointer fixed |
| Double click | 200 ms easeOut back to the initial fitted view |
| Top toolbar | Left: toggle source / chart view. Right: copy source, download SVG, download PNG |
| Bottom-right zoom pill | Zoom in / out / reset (pill floating in the corner, unaffected by chart zoom), anchored to the viewport centre, 200 ms easing |

During gestures the transform layer is written directly by `use-zoom`, bypassing React state, so no re-render happens per frame. Zoom ranges from 0.25× to 8×, with no inertial fling. Scaling uses 2D `translate + scale` (**no compositor promotion**) and the SVG re-renders at the current scale every frame, so magnification stays sharp. If a host ancestor applies `filter` / `backdrop-filter` / `translateZ(0)`, the browser re-rasterises and that part is outside package control.

When the SVG exposes no natural size (no `viewBox`/dimensions), interaction degrades to a static display instead of a blank area. Export uses the SVG currently on screen (no re-render); PNG is drawn on a 2× canvas over `--lkes-chart-bg`.

`/mermaid` also exports callable helpers — `downloadSvg`, `downloadPng`, `prepareSvg`, `svgToPngBlob` — so custom toolbars need no rewrite.

### 11.7 Relation to fenced code

A three-backtick fence tagged `mermaid` keeps its **unchanged** meaning (still a code block). Both forms coexist:

- The container form is rendered by this package (source skeleton → interactive chart);
- The fenced form stays the host's decision (it may keep rendering diagrams through its code-block component).

Migration is up to the host; the package ships no repo-wide rewriter.

### 11.8 Security

- `securityLevel: "strict"` is fixed and not configurable: HTML tags and click events inside diagram source are disabled.
- Rendered output is sanitised by DOMPurify (`svg` profile, `<style>` kept) before injection: no scripts, no event attributes.
- Diagrams are inline SVG only and never go through the `href` channel; `Image` URL whitelisting is unaffected.

### 11.9 Theme (built in, host-independent)

`<Mermaid>` ships **both light and dark palettes** and works with zero configuration, reading **no host CSS variables**.

| Layer | Where | Priority |
|---|---|---|
| JS config | `configureChartTheme({ light, dark })` | Highest (once set, SVG colors come from it, not CSS) |
| CSS override | Redeclare `--lkes-chart-*` in any scope | Middle |
| Built-in defaults | Two literal sets in `styles/mermaid.css` component scope | Fallback |

Light/dark is decided by the **nearest `.dark` ancestor** (`[data-theme="dark"]` also supported); no theme-variable naming is assumed.

| Variable | Light | Dark |
|---|---|---|
| `--lkes-chart-bg` (card / chart background) | `#ffffff` | `#161c22` |
| `--lkes-chart-surface` (toolbar / zoom pill) | `#f6f9f8` | `#1c262c` |
| `--lkes-chart-fg` (text / buttons) | `#1f2937` | `#e8eef2` |
| `--lkes-chart-muted` (secondary text) | `#6b7280` | `#9aa8b0` |
| `--lkes-chart-node` (node fill) | `#e7f0ea` | `#1e3037` |
| `--lkes-chart-node-border` (node stroke) | `#c9d8cf` | `#2f4a52` |
| `--lkes-chart-line` (edges) | `#9aa8a0` | `#7a8a92` |
| `--lkes-chart-accent` (source view, hover) | `#01c4b6` | `#19d3c5` |
| `--lkes-chart-series-1..6` (slices / branches) | teal/blue/indigo/violet/pink/orange | same, first `#19d3c5` |

```ts
import { configureChartTheme } from "@heikeson/md-engine/mermaid";

configureChartTheme({
  // pass only what changes; the rest keeps its default
  light: { node: "#fff3d6", nodeBorder: "#e8d9b0" },
  dark: { node: "#2a2418", nodeBorder: "#4a3f28" },
});
```

`ChartTokens` fields: `bg`, `fg`, `node`, `nodeBorder`, `line`, `series` (six or more colors), `fontFamily`. Read and reset with `getChartTheme()` / `resetChartTheme()` / `hasCustomChartTheme()`.
