## 一、背景：为什么现在需要

| 事实 | 依据 |
|---|---|
| 本仓库**没有 dev server**，调试靠宿主 | `docs/构建与发布.md` 第六节：「本包不提供 dev server，调试在宿主项目内进行」 |
| 宿主已删除 `packages/md-engine` 本地副本 | `blog-heikeson2026/package.json` 写 `"@heikeson/md-engine": "^0.1.0"`，`packages/md-engine` 目录不存在 |
| 包已发布到 npm（0.1.0，2026-10-25） | `npm view` 返回 `latest: 0.1.0`；宿主 `node_modules` 中只有 `dist/` |

**推论**：改动 `src/` 后想看见效果，当前唯一路径是「改版本号 → `npm publish` → 宿主升级 → 起宿主 dev」。中间还夹一次不可逆的版本发布，反馈循环以分钟计，且不允许试验性改动。

此外本包有两类内容天然需要"看"才能验收：

1. **样式**：`styles/engine.css` 全量 `@apply`，作用域挂 `.prose-site`，颜色全部引用宿主语义令牌（`border-border`、`bg-muted`、`text-muted-foreground`、`border-primary`、`ring-ring`、`bg-background`）。改一个 `@apply` 是否踩空，只能在渲染后才知道。
2. **容器交互**：`Accordion` / `Tabs` / `Image` 灯箱依赖 React 状态，静态 HTML 看不出行为。

## 二、目标与非目标

### 2.1 目标

1. 在**本仓库内**起一个浏览器可访问的渲染页面，改 `src/` 或 `styles/` 即时生效（热更新）。
2. 覆盖全部语法面：8 容器 + 7 子项、属性、自闭合、GFM、公式、代码块元信息。
3. 覆盖容错面：未闭合、未知标签、超限嵌套、非法协议 —— 并在页面上**直出 `diagnostics`**。
4. 明暗两套主题可切换（验证 `dark:` 分支）。
5. 视觉尽量接近宿主：复用同一套语义令牌名（值可简化）。
6. **不影响发布包**：新增目录不进 `files` 白名单，不新增运行依赖。

### 2.2 非目标

- 不做产品化站点，不做部署，不做鉴权。
- 不替代宿主的文章页；宿主特有的插件（代码高亮 shiki、mermaid、TOC、评论）不在本地渲染范围。
- 不追求像素级等同宿主（宿主有自己的 `prose.css` / `heading.css` 等，属于站点排版，不属引擎职责）。

## 三、方案对比

| # | 方案 | 形态 | 热更新 | 真实度 | 增量依赖 | 成本 | 结论 |
|---|---|---|---|---|---|---|---|
| **A** | **Vite + React + Tailwind 4 playground** | 浏览器 dev server（`dev/`） | ✅ HMR | 高（真实 React 组件 + 真实 `@apply` 管线） | `vite`、`@vitejs/plugin-react`、`tailwindcss`、`@tailwindcss/vite`、`react`、`react-dom`（均 devDeps） | 0.5 天 | **推荐** |
| B | Node SSR 静态快照 | 脚本把 fixtures 渲染成 `preview.html` | ❌ | 中（无交互） | 仅需 Tailwind CLI 编译样式 | 0.5 天 | 可选，补 CI 快照 |
| C | Storybook | 组件级故事集 | ✅ | 中高 | `storybook` 全家桶（10+ 包） | 2 天+ | 过重，否决 |
| D | 在宿主里开一个 `/dev/markdown` 页 | 站在 blog 项目里看 | ✅ | 最高 | 无 | 0.2 天 | 违背「本仓库是唯一实现地」，且改包仍要发版才有可能生效，否决 |

### 3.1 为什么否掉 C / D

- **C Storybook**：本包只有 15 个容器 + 1 个渲染器 + 1 个编辑器，Storybook 的配置与包体成本远超收益；且它自带一套 Tailwind 集成坑，等于把 A 的样式问题再叠一层。
- **D 宿主内页面**：最真实，但宿主消费的是 npm 上的 `dist`。要在宿主里看到 `src` 的改动，仍需 `npm link` 或发版，等于把"快速反馈"这个核心诉求让掉了；同时会把开发调试代码写进另一个仓库。

### 3.2 B 的价值（建议后续追加，不阻塞 A）

`renderToStaticMarkup` 把 fixtures 渲成 HTML，可直接做成 `md → HTML` 的**快照基线**，用于回归：改动前后 diff 一眼看出渲染差异，且天然适合放进 CI（无需浏览器）。缺点是无 HMR、无交互。

## 四、推荐方案 A 的落地拆解（待放行后执行）

### 4.1 目录

```
dev/                        # 新增，不进发布包（package.json files 未包含）
├─ index.html
├─ main.tsx                 # 挂载 React
├─ App.tsx                  # 左：Markdown 文本域（可切 fixtures）；右：<MarkdownRenderer />
│                           # 底部：diagnostics 列表 + serialize 往返结果
├─ theme.css                # 最小主题令牌 + @custom-variant dark + .prose-site 基础排版
├─ vite.config.ts           # root 指向 dev/，端口 5180
└─ fixtures/
   ├─ containers.md         # 全部容器 / 子项 / 属性 / 自闭合
   ├─ edge-cases.md         # 未闭合、未知标签、超深嵌套、非法协议
   └─ kitchen-sink.md       # GFM 表格、任务列表、脚注、公式、代码块 meta
```

### 4.2 样式怎么补（关键难点）

`engine.css` 里的 `@apply border-border`、`bg-muted` 等依赖宿主的语义令牌，本仓库**没有** Tailwind 主题。方案：

```css
/* dev/theme.css 骨架（示意） */
@import "tailwindcss";
@import "../styles/engine.css";     /* 真实源文件，改它即热更新 */

@custom-variant dark (&:is(.dark *));

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-border: var(--border);
  --color-primary: var(--primary);
  --color-ring: var(--ring);
}

:root { /* 取值对齐宿主 theme.css 的明色 */ }
.dark { /* 取值对齐宿主 theme.css 的暗色 */ }
```

要点：令牌名必须与宿主一致（`.prose-site` 契约的一部分），值取宿主的近似值即可，不复制宿主的整套排版规则。

### 4.3 页面能力清单

| 区域 | 内容 |
|---|---|
| 左栏 | fixtures 下拉切换 + 可编辑文本域（改完即时渲染） |
| 右栏 | `<MarkdownRenderer content={md} className="prose-site" />`，站点同款容器类 |
| 底栏 | `parse()` 的 `diagnostics`（code / 位置 / 消息）、`roundtrip()` 是否逐字一致 |
| 顶栏 | 明暗切换、容器深度上限提示、`sourcePositions` 开关 |

> 编辑器（`<MarkdownEditor />`）是否一并放进页面，见待确认问题 Q2。

### 4.4 命令与端口

```bash
npm run dev        # vite，http://localhost:5180
```

端口取 5180（避开宿主 3000），且**只在本仓库执行**，不影响宿主正在跑的 dev 进程。

## 五、风险与约束

| 风险 | 影响 | 应对 |
|---|---|---|
| 新增 6 个 devDependencies | 改 `package.json` + `package-lock.json` | 全部进 `devDependencies`；`files` 白名单不含 `dev/`，发布包不受影响 |
| Tailwind 4 版本漂移 | `@apply` 语义类解析差异 | 与宿主对齐版本（宿主为 `tailwindcss@4.3.3`） |
| 本地渲染与宿主真实效果仍有差距 | 误判"本地好看、线上不对" | 文档写明：本地只验证引擎层；排版差异以宿主为准 |
| 代码高亮 / mermaid 不在包内 | 本地代码块是纯 `<pre>` | 通过 `RenderConfig.rehypePlugins` 注入可选项，默认不接（避免把宿主的 shiki 依赖搬进仓库） |
| katex 样式需手动引 | 公式排版错乱 | `dev/theme.css` 内 `@import "katex/dist/katex.min.css"` |
| `dev/` 误入 git 忽略清单或发布清单 | 开发目录丢失 / 包体膨胀 | 只加不进 `.gitignore`；`files` 不动 |

### 9.3 实施中发现的引擎问题（未修改 `src/`，待决策）

| # | 现象 | 位置 | 影响 |
|---|---|---|---|
| 1 | 数学公式往返被转义：`\int_0^1 x^2 \, dx` → `\int\_0^1 x^2 , dx`（`\_` 与 `\,` 被当普通文本转义） | `serialize.ts` 的 math/inlineMath handler 缺省，落到 text 规则 | 公式经过一次保存即变形，违反「往返逐字一致」 |
| 2 | 未闭合容器序列化会在文末补一个闭合标签 | jsx `toMarkdown` handler | 内容不丢，但二次保存会多出标签 |

第 1 条已记录为 `fixtures/kitchen-sink.md` 的「已知差异」标注，底栏按琥珀色提示、不判回归。
