## 八、架构特点与设计模式

- **单向管线，收发对称**：`md → AST → md` 逐字一致；容器节点在 mdast 层统一为 `jsxBlock` 自定义节点，渲染时由 hast handler 转换，序列化由 toMarkdown handler 输出。
- **分层架构（模块边界硬约束）**：
  - 声明层（registry/policy）禁止依赖 React/DOM；
  - 词法层（syntax）禁止依赖 mdast/React；
  - 渲染层必须 SSR 安全（不访问 window/document）；
  - 编辑器层不得被主入口导出（否则 CodeMirror 进入阅读页 chunk）。
- **容错降级原则**：不崩、不吞内容；未知标签交回内置 html flow，未闭合降级为文本并产出 `UNCLOSED_TAG`，超限嵌套降级为 source 块。
- **构建产物发布**：`tsup` 产出 `dist/`（JS + `.d.ts` + sourcemap），三个入口相互隔离；样式 `styles/engine.css` 保留 `@apply` 源码，交由使用方 Tailwind 4 管线处理。
- **契约三约束（不可破坏性变更）**：语法只增不改（C1）、配置只增不改（C2）、样式随包走（C3）。

## 十三、注意事项与建议

- **已发布**：`0.2.0` 已上线 npm（tag `v0.2.0`），产物为 `tsup` 构建的 `dist` + `styles`，源码不入包。发布配置（`.npmrc`/`.npmignore`/`LICENSE`/`publishConfig`/`prepublishOnly`）均已就绪，后续发版只需改版本号 + `npm publish`。详见 `docs/构建与发布.md` 与 `docs/npm发布配置/需求文档.md`。
- **本仓库是唯一实现地**：下游只消费 npm 包，**改代码必须重新构建并发版才对使用方生效**。
- **无 CI**：发布为手动流程，建议后续加 GitHub Actions 做 typecheck + 自动发布。
- **未闭合往返已修**（2026-10-26）：`policy.collectUnclosed()` 命中时回写 `data.closed = false`，`jsx` 序列化据此不补闭合标签。已知取舍：判定靠"原文区间内是否出现 `</Name>`"，同名嵌套或正文出现该字面量时会少报。详见 `docs/未闭合容器序列化/需求文档.md`。
- **四个诊断码均已实现**（2026-10-26）：`UNCLOSED_TAG` / `DEPTH_EXCEEDED` / `UNSAFE_HREF`（容器属性 + 普通链接/图片）/ `UNKNOWN_TAG`（未注册标签）。安全边界是 **hast 闸门** `rehype-safe-urls`：所有元素的非法 `href` → `#`、非法 `src` → 删除，早于组件映射，使用方覆写 `a`/`img` 也绕不过；组件内 `isSafeHref` 仅作兜底。
- **公式往返已修**（2026-10-26）：`parse.ts` 与 `serialize.ts` 对称接入 `math` / `mathFromMarkdown` / `mathToMarkdown`，修复 `$…$` 被当普通文本转义（`\_`、`\,`）的问题；两个 math 包已从幽灵依赖升为直接依赖。详见 `docs/数学公式往返修复/需求文档.md`。
- **无测试框架**：往返一致性目前靠 `dev/` 的 fixtures 自检（`npm run snapshot` 会打印不一致项并落盘 `roundtrip-*.md`），建议后续把这些样例直接搬进 vitest。
- **本地开发渲染已就绪**（2026-10-26）：`npm run dev` 起 5180 端口 playground（渲染 + 编辑器联调），`npm run snapshot` 出静态快照。`dev/` 不在 `files` 白名单，发布包不受影响；新增的 6 个开发依赖只进 `devDependencies`。
