# 未闭合容器的序列化 —— 需求文档

> @file 需求文档.md
> @description 未闭合容器的序列化行为：当前会在文末自动补 `</Name>`，与原文不一致。本文只做分析与方案，未改代码。
> @created 2026-10-26 22:07
> @updated 2026-10-26 22:13
> @status 已实施

## 一、现象

`dev/fixtures/edge-cases.md` 的首个 `<Callout type="warn">` 故意不闭合，往返后：

```diff
  ## 非法协议
  ...
+
+</Callout>
```

即：**原文没有闭合标签，序列化结果在文件末尾多出一个**。内容本身不丢，但：

1. 与原文不再逐字一致（违反 README 验收 1）；
2. 用户第二次保存后，未闭合的"坏"内容被静默"修好"，行为不可预期。

## 二、根因

| 位置 | 现状 |
|---|---|
| `src/syntax/jsx-mdast.ts` `handleJsxBlock()` | 非自闭合时**无条件**输出 `<Name …>\n\n{inner}\n\n</Name>` |
| 同上，`exitOpenTag()` | `node.data = { closed: true }`，即默认就当已闭合 |
| `src/policy.ts` `collectUnclosed()` | 只产出 `UNCLOSED_TAG` **诊断**，不回写节点状态 |

也就是说：解析层其实知道"这个块没闭合"（诊断能报出来），但这个结论只走到了 UI，没有走到序列化。

## 三、方案对比

| # | 方案 | 做法 | 评价 |
|---|---|---|---|
| **A** | 诊断结论写回节点 | `collectUnclosed()` 里把 `block.data.closed = false`；`handleJsxBlock()` 读该标记，未闭合时**不输出** `</Name>` | **推荐**：改动小、单点判定、序列化与诊断口径一致 |
| B | 序列化时比对原文位置 | 用 `node.position` 判断原文结尾是否有闭合标签 | 不可行：`serialize()` 只拿到 mdast，没有原文（`position` 无文本） |
| C | 保持现状（自愈） | 不改，文档写明"补闭合"是预期 | 可选兜底：能保证产出的 Markdown 一定合法，但与"逐字一致"永久冲突 |

选 **A**，并把"自愈"这个诱人的替代方案记在文档里，避免以后反复争论。

## 四、实施清单

| 文件 | 改动 |
|---|---|
| `src/policy.ts` | `collectUnclosed()` 命中时写 `block.data.closed = false`（`data` 不存在则创建） |
| `src/syntax/jsx-mdast.ts` | `handleJsxBlock()`：`node.data?.closed === false` 时只输出 `<Name …>` + 内容，不补闭合标签 |
| `src/syntax/jsx-mdast.ts` | 文件头说明补上"未闭合不补标签"的口径 |
| `dev/fixtures/edge-cases.md` | 往返差异应显著缩小；`known-diff` 标注保留（降级内容仍会变） |

不动：`jsx-flow.ts`（词法）、`render.tsx`、`blocks.ts`、`files` 白名单。

## 五、风险

| 风险 | 说明 | 应对 |
|---|---|---|
| 嵌套未闭合 | 外层未闭合、内层正常闭合时，不能把内层也当未闭合 | 标记按节点独立写，只影响命中诊断的那个节点 |
| 产出的 Markdown 变"非法" | 不补标签意味着序列化结果仍需能被再次解析（未闭合本身是允许的写法，解析层照常容错） | 验收里加"序列化结果再解析不崩、诊断仍是 1 条 `UNCLOSED_TAG`" |
| 编辑器保存行为变化 | 之前保存会"顺手修好"，之后保持未闭合 | 这正是目标；需在 README 容错表里写明 |

## 六、验收

- [ ] `roundtrip("<Callout type=\"warn\">\n\n正文\n")` 不再追加 `</Callout>`
- [ ] 正常闭合的容器往返结果不变（`containers.md` 仍 strict 通过）
- [ ] 序列化结果再解析：不崩，`UNCLOSED_TAG` 仍只报 1 条
- [ ] `dev/fixtures/edge-cases.md` 的差异从"多出闭合标签"缩小为"仅降级内容差异"
- [ ] `npm run typecheck` / `npm run build` / `npm run snapshot` 全绿

## 七、明确不做

- 不改"未闭合就渲染到文末"的**渲染**语义（这是既有契约，宿主历史内容依赖它）。
- 不新增"自动修复用户内容"的能力（自愈属产品决策，非引擎默认行为）。

## 八、实施结果（2026-10-26 22:13）

### 8.1 实际改动

| 文件 | 改动 |
|---|---|
| `src/policy.ts` `collectUnclosed()` | 命中时写 `block.data = { ...data, closed: false }` |
| `src/syntax/jsx-mdast.ts` `handleJsxBlock()` | `node.data?.closed === false` 时不输出闭合标签 |
| `dev/fixtures/edge-cases.md` | 未闭合段移到最后；补「列表项缩进」与「非法协议无诊断」说明 |
| `dev/snapshot.tsx` | 增加每篇样例的诊断汇总输出，便于脚本核对而非肉眼判断 |

### 8.2 验证

| 用例 | 往返 | 诊断 |
|---|---|---|
| `<Callout type="warn">` 未闭合 | 逐字一致 ✅（不再追加闭合标签） | `UNCLOSED_TAG` |
| 正常闭合 | 逐字一致 ✅（行为不变） | 无 |
| 外层未闭合 / 内层闭合 | 逐字一致 ✅（内层保留自己的闭合标签） | `UNCLOSED_TAG` |
| `edge-cases` 整篇 | 差异缩小到仅"降级内容"，尾部不再多出 `</Callout>` | `DEPTH_EXCEEDED`, `UNCLOSED_TAG` |
| `npm run typecheck` / `build` / `pack` | 通过；清单 18 文件，不含 `src` / `dev` | — |

### 8.3 实施中发现的坑（已写进 fixtures 与 README）

1. **判定靠原文区间查找**：`hasCloseTag()` 在块的 `position` 区间内找 `</Name>`。因此
   正文里只要**出现该标签的字面量**（例如文档里写「序列化不再补 `</Callout>`」），
   就会把真正未闭合的块误判成已闭合。本次就在 fixture 里踩到了，已改写正文措辞。
2. **同名嵌套的误判是既有取舍**：`policy.ts` 注释写明"宁可少报"——外层未闭合、
   内层同名闭合时不会报 `UNCLOSED_TAG`，序列化仍会补标签。若要修，需要基于 token 栈
   重做未闭合判定，属独立需求。

### 8.4 顺带核对出的文档缺口（未改代码）

- `UNSAFE_HREF`、`UNKNOWN_TAG` 两个诊断码**只有类型声明，代码里从不产出**；非法协议目前
  只在渲染层由 `cards.tsx` / `file.tsx` 的 `isSafeHref` 拦成不可点击。README 第 6.4 节的
  表述已按实际行为调整。
