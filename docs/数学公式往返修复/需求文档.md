## 一、现象（实测证据）

用本地开发渲染的往返自检跑 `dev/fixtures/kitchen-sink.md`，得到首个差异 @210：

```diff
 ## 数学公式
-
-行内公式 $a^2 + b^2 = c^2$。
-
-$$
-\int_0^1 x^2 \, dx = \frac{1}{3}
-$$
+
+行内公式 \$a^2 + b^2 = c^2\$。
+
+$$
+\int\_0^1 x^2 , dx = \frac{1}{3}
+$$
```

三处破坏：

| 输入 | 序列化后 | 后果 |
|---|---|---|
| `$a^2 + b^2 = c^2$` | `\$a^2 + b^2 = c^2\$` | 美元符被转义，公式变成字面文本 |
| `\int_0^1` | `\int\_0^1` | 上下标分隔符 `_` 被转义，公式语义改变 |
| `\,`（细间距） | ` , ` | 反斜杠转义被吃掉，间距命令丢失 |

## 二、根因

本包有**两条互不相干的管线**，对 math 的支持不对称：

| 管线 | 位置 | 是否接入 math 扩展 |
|---|---|---|
| 渲染 | `src/render.tsx` | ✅ `.use(remarkMath)`（第 92 行） |
| 解析 / 序列化 | `src/parse.ts` / `src/serialize.ts` | ❌ 只有 `gfm()` + `jsxBlocks()` |

`parse.ts` 的实际注册：

```ts
extensions: [gfm(), jsxBlocks()],
mdastExtensions: [gfmFromMarkdown(), jsxFromMarkdown()],
```

没有 `math()` / `mathFromMarkdown()`，于是 `$...$` 在 parse 阶段就是**普通文本**：

1. 文本节点里 `_` 属于需转义字符 → `serialize` 写出 `\_`；
2. 文本里 `\,` 被 micromark 当作「转义逗号」→ 值变成 `,`，反斜杠丢失；
3. `$` 同理被当作文本特殊字符转义。

所以**渲染是对的、保存是错的**：编辑器里看到公式正常，一失焦（`normalizeMarkdown` + 序列化）内容就被改写。这直接违反 README「验收 1：`md → AST → md` 逐字一致」。

## 三、影响面

| 面 | 影响 |
|---|---|
| 编辑器保存 | 含公式的文章保存一次即变形，且是**不可逆**的内容损坏 |
| 契约 | 违反 `对接契约.md` 的往返承诺；宿主若做内容迁移/备份会踩到 |
| 诊断 | `parse().diagnostics` 与块索引把公式当文本，编辑器无法识别公式块 |
| 渲染 | 无影响（`remarkMath` 独立注册） |

## 四、方案对比

| # | 方案 | 做法 | 评价 |
|---|---|---|---|
| A | 只补序列化 handler | 在 `serialize.ts` 注册 `math` / `inlineMath` handler | **无效**：parse 根本不产 math 节点，handler 永远不会被调用 |
| **B** | **parse + serialize 都接 math** | `parse.ts` 加 `math()` / `mathFromMarkdown()`；`serialize.ts` 加 `mathToMarkdown()` | **推荐**：与渲染管线对齐，往返由 math 节点自身承载原始 value，`\`、`_`、`,` 原样保留 |
| C | 在 `normalizeMarkdown` 里后处理 | 用正则保护 `$...$` 段 | 治标：只挡编辑器一条路，`serialize()` 对外仍然坏；正则处理嵌套/代码块极易误伤 |

选 **B**。理由：`mdast-util-math` 系列是 remark-math 的官方底层（本项目已在用 `remark-math`），节点 value 就是公式原文，序列化时不再经过文本转义。

## 五、实施清单

| 文件 | 改动 |
|---|---|
| `src/parse.ts` | 注册 `math()`（micromark）与 `mathFromMarkdown()`（mdast），与 `gfm` 并列 |
| `src/serialize.ts` | 注册 `mathToMarkdown()` |
| `package.json` | 把 `mdast-util-math`、`micromark-extension-math` 从**传递依赖**升为**直接依赖**（当前只由 `remark-math` 带入，不显式声明属于幽灵依赖） |
| `dev/fixtures/kitchen-sink.md` | 修好后重跑快照：若往返一致，把标注从 `known-diff` 改回 `strict` |

不动：`render.tsx`、`blocks.ts`、`policy.ts`、`format.ts`、`tsup.config.ts`、`files` 白名单。

## 六、风险

| 风险 | 说明 | 应对 |
|---|---|---|
| `parse()` 输出新增 `math` / `inlineMath` 节点 | `blocks.ts` 会把它当作 `visual`（type=`math`），编辑器出块 UI 可能出现未识别类型 | 先核对 `blocks.ts` 的 `toBlock` 兜底（`unknown` 走 `visual`，不会崩）；编辑器块 UI 若不处理该类型，按普通块呈现 |
| 序列化的空行/缩进与原文不完全一致 | block math 规范形式可能是 `$$\nvalue\n$$` | 用 fixtures 实测；能逐字一致就升 `strict`，否则保留 `known-diff` 并写明差异 |
| `singleDollarTextMath` 行为差异 | 渲染侧 remark-math 默认开启，parse 侧 `math()` 默认同值 | 两侧显式保持默认，不各写一套参数 |
| 新增直接依赖 | `package-lock.json` 变化 | 两个包已在树内（`mdast-util-math@3.0.0`、`micromark-extension-math@3.0.0`），升为直接依赖不引入新版本 |

## 七、验收

- [ ] `roundtrip("行内 $a^2+b^2=c^2$ 与 $$\int_0^1 x^2 \, dx$$")` 与输入逐字一致
- [ ] `dev/fixtures/kitchen-sink.md` 往返一致（或差异被明确记录并降级标注）
- [ ] 渲染不回归：`npm run snapshot` 产物中公式仍是 KaTeX 结构（`.katex` 存在）
- [ ] `npm run typecheck` 零错误
- [ ] `npm run build` 通过，`npm pack --dry-run` 清单不变（仍不含 `src`、`dev`）
- [ ] 本地 playground 底栏由「已知差异（琥珀）」变为「逐字一致（绿）」

## 八、明确不做

- **未闭合容器的序列化补标签问题**（`</Callout>` 会自动补到文末）：属于 jsx handler 的语义决策，另立需求。
- 不做公式的「格式美化」（如自动补空格、统一 `$$` 换行），只保证**不改动用户内容**。

### 10.3 遗留口径（非缺陷）

- **表格对齐**：GFM 序列化会按列宽补齐空格，内容不变。fixtures 采用规范对齐形式，避免每次比对都被这一项干扰。
- **容错样例仍为 `known-diff`**：未闭合与超深嵌套按设计降级，序列化必然与原文不同；要消除它就得改变降级语义，不在本需求范围。
- **未闭合容器补标签**：序列化会在文末补 `</Name>`，仍按原计划另立需求。
