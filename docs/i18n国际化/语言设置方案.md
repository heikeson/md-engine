## 一、先把问题切干净：语言由三层共同决定

| 层 | 谁 | 决定什么 | 例子 |
|---|---|---|---|
| L1 终端用户偏好 | 用户自己 | 我在这个站点想用哪种语言 | 站内语言切换器、浏览器语言、账户设置 |
| L2 应用路由 / 服务端 | 宿主应用 | 这个 URL / 这个请求对应哪种语言 | `/en/docs`、`example.de`、`Accept-Language` |
| L3 引擎 | 本包 | 收到 locale 后**只做消费**：选包、算复数、定方向 | — |

**L1/L2 属于宿主，L3 只接收。** 只有宿主知道 URL 结构与账户体系；库自己去读环境就等于替宿主做策略决定，且必然在 SSR 下出错。

## 二、"根级 Provider"是什么意思

一句话：**在组件树顶端设一次值，底下所有组件自己往上找，不用逐个传 prop**。技术上是 React Context，本包内部已经有 `UITextProvider`（`src/internal/text.tsx:127`），只是没对外开放。

现在的问题用 site 举例最清楚。site 里用到引擎的地方有 4 处：

```
site/src/layout/DocsLayout.tsx:87     <MarkdownRenderer …/>
site/src/pages/Home.tsx:69            <MarkdownRenderer …/>
site/src/pages/Home.tsx:109           <MarkdownRenderer …/>
site/src/pages/Playground.tsx:201     <MarkdownEditor …/>
```

- **只有 props 的方案**：这 4 处每处都要写 `config={{ locale, messages }}`。而 `SITE_RENDER_CONFIG` 是模块级常量（`site/src/components/render-config.ts:15`），一旦要和 locale 拼在一起，就变成每次渲染新建对象，破坏 `MarkdownRenderer` 内部的 `useShallowStable` 稳定化。将来再加第 5 个用法，还会漏传——漏传的表现是"这一块突然变中文"，很难在评审里发现。
- **有根级 Provider 的方案**：在 `site/src/App.tsx` 外面包一次：

```tsx
// 只在这里写一次
<MdEngineProvider locale={locale} messages={dict}>
  <Header /> {page} <Footer />
</MdEngineProvider>
```

4 处调用点一个都不改，且以后新增用法天然继承。

Provider 本身**不含任何全局可变状态**：值完全来自 props，可嵌套、可重复渲染。服务端多请求并发复用同一模块也不会串语言。

### 合并语义（两层不同规则）

| 字段 | 语义 | 理由 |
|---|---|---|
| `locale` | **覆盖**：就近一个非空值生效 | 语言是单值，不存在"合并两种语言" |
| `messages` | **逐键叠加**：内层覆盖同键，未给的键继承外层 | 宿主可全局铺术语表，局部再改个别词 |

## 三、四级优先级（含 localStorage）

```
① 组件 props:   <MarkdownRenderer config={{ locale, messages }} />
                        ↓ 未给
② 根级 Provider: <MdEngineProvider locale messages>  …包住整个应用
                        ↓ 未给（且已挂载到客户端）
③ localStorage["lkes-md-lang"]   用户上次的选择
                        ↓ 未给
④ 内置默认:      zh-CN + 包内中文全量文案
```

### 3.1 `lkes-md-lang` 契约

```ts
/** 默认存储键；宿主可换 */
export const DEFAULT_LOCALE_STORAGE_KEY = "lkes-md-lang";

export interface LocaleStorage {
  get(): string | null;
  set(locale: string): void;
  remove(): void;
}

export interface LocaleStorageOptions {
  /** 默认 "lkes-md-lang" */
  key?: string;
  /** 完全自实现（自带 cookie / KV / 内存都能接） */
  get?: () => string | null;
  set?: (locale: string) => void;
  remove?: () => void;
}

/** 默认实现：localStorage + 键名；非浏览器环境 get 恒为 null，set 为空操作 */
export function createLocaleStorage(options?: LocaleStorageOptions): LocaleStorage;
```

三条设计约束：

1. **读取只在客户端挂载后**。SSR / 预渲染阶段 `localStorage` 不存在，读到的必然是默认值；如果服务端与客户端读到的不同，就是 hydration mismatch。所以 ③ 只可能在 `useEffect` 之后生效。
2. **库不主动写**。写入由宿主显式调用 `localeStorage.set(locale)`（例如语言切换器的 onClick）。库有副作用会让"渲染函数"变成不幂等操作，快照测试与 RSC 缓存都会受影响。
3. **值用 BCP-47**（`zh-CN` / `en-US`），不用 `zh`/`en` 短码。短码留给 URL 段，两者之间用 `toRouteSegment()` / `fromRouteSegment()` 转换，避免"存储层与路由层各有一套方言"。

### 3.2 为什么不能"读一次 localStorage 就当准了"

③ 生效意味着**首帧是 ④、挂载后才可能变 ③**——一定会闪一次。这不是疏忽，是物理约束：预渲染产物里不可能包含每个用户各自的语言。

所以**能靠路由确定的页面，必须靠路由确定**（优先级 ②），localStorage 只用于两种场景：

- 无语言路由的页面（如 `/playground` 若不做 `/en/playground`）；
- 宿主不做路由 i18n 的裸用场景。

> 结论：site 要做路由翻译，所以 site 的文档页永远走 ②，**零闪烁**；localStorage 只承担"记住偏好"与"无路由兜底"。

## 四、库不做什么

| 不做 | 理由 |
|---|---|
| 读 `navigator.language` | 服务端无此对象；SSR 首屏与客户端不一致 = hydration mismatch + 闪烁 |
| 读 `document.documentElement.lang` | 同上（客户端才有）。隐式依赖 DOM 后组件不再纯 props 驱动，快照不可复现 |
| 读 cookie / header | 库不知道 cookie 名，也无法在 RSC 边界访问请求对象 |
| **自动写** cookie / localStorage | 渲染必须幂等；写入由宿主显式调用 `set()` |
| 输出 `dir` 属性 | 与宿主 `<html dir>` 冲突、嵌套 Provider 会出现两个方向声明点。见 §六 |
| 内置语言切换器 UI | 与宿主设计系统冲突；且"切换后跳哪个 URL"是路由问题 |

提供两个**纯函数**作为 opt-in 工具，由宿主决定是否调用：

```ts
/** 从 BCP-47 候选里挑第一个可用的（解析 Accept-Language 用） */
resolveLocale(candidates: readonly string[], available?: readonly string[]): string
/** 一次性探测：html[lang] → navigator.languages → 默认 zh-CN。只在 effect 里调 */
detectLocale(): string
```

## 五、未翻译键的回退链

```
messages[key]                          ← 宿主逐键覆写（最高）
   ↓ 缺
内置包[locale][key]                     ← 内置 zh-CN / en-US 全量
   ↓ 缺
内置包[fallbackLocale ?? "zh-CN"][key]   ← 可配，默认中文
   ↓ 缺
内置包["zh-CN"][key]                    ← 最终保底，永不 undefined
```

`fallbackLocale` 是宿主可选项：`/ja/` 站点通常希望未翻译部分显示**英文**而不是中文，配置 `fallbackLocale: "en-US"` 即可。默认保持中文（包的主语言）。

## 六、切换语言时会发生什么（运行时契约）

### 6.1 现状有个必须修的缺陷

`MarkdownEditor.tsx:200` 的重建依赖数组：

```ts
}, [viewMode, config?.readOnly, text.editorWrapPlaceholder]);
```

`text.editorWrapPlaceholder` 在依赖里 → **只要文案变（换语言、甚至宿主每次渲染传新对象），CodeMirror 实例就被销毁重建**：丢光标、丢撤销栈、丢滚动位置。

### 6.2 契约：locale / messages 变化只允许"热更新"

| 部分 | 语言切换时的正确反应 |
|---|---|
| 工具栏 / 状态栏 / 视图按钮 | React 重渲染（本就是 `useUIText()` 读取） |
| 预览区 | 重渲染，但 **AST 不重算**（解析结果与语言无关，`useMemo` 依赖不含 locale） |
| CodeMirror 文档内容 | 完全不感知 |
| placeholder 扩展 | `Compartment.reconfigure()` 热替换，不重建 editor |
| 快捷键 `Mod-b` 等 | 不变（快捷键是惯例，不是文案） |
| 光标 / 选区 / 滚动 / 撤销栈 | 不得重置 |

实现要求：重建依赖数组只保留**结构性**因素（`viewMode`、`readOnly`），`wrapPlaceholder` 走 ref 通道或 `Compartment`。

> 附带收口旧 bug：`EditorConfig.placeholder` 声明了却从未传给 `createEditor`。接线后优先级为 `config.placeholder` > `messages.editorPlaceholder` > 内置默认。

### 6.3 方向变化（LTR → RTL）

`dir` 改变会整页重排，属宿主切 `<html dir>` 的行为，必然一次重排，库不干预。库只保证 CSS 全逻辑属性（`styles/` 18 处物理属性迁移），`dir` 一变立即正确，无需 JS。

### 6.4 方向为什么不由库输出 `dir`

| 方案 | 问题 |
|---|---|
| 每个组件根元素输出 `dir` | 与宿主 `<html dir>` 冲突；嵌套时同一子树两个 `dir`，排查困难 |
| Provider 内包一层 `<div dir>` | 无谓 DOM 层级，破坏宿主的 flex/grid 布局假设 |
| **只依赖文档根 `dir` + CSS 逻辑属性**（选此） | 单一事实源，库不制造第二个方向声明点 |

库内需要方向的地方只有两类：① 需要判断左右的 JS 行为（滚动同步横向对齐）；② 方向性图标。都读 `useLocale().direction`，**不输出 DOM 属性**。宿主若忘了设 `<html dir="rtl">`，逻辑属性按 LTR 解析——这条写进文档前置条件。

## 七、locale 一个值驱动三件事

| 用途 | 用法 | 注意 |
|---|---|---|
| 选内置语言包 | `LOCALES[locale]` | 未内置 → BCP-47 截断 → `fallbackLocale` → `zh-CN` |
| 复数 / 数字格式 | `new Intl.PluralRules(locale)` | 按 locale 做 `Map` 缓存（纯函数映射，非可变状态） |
| 书写方向 | `isRTL(locale)` | `ar` / `he` / `fa` / `ur` |

三者必须同源。拆成三个 prop 会出现"英文文案 + 中文复数规则 + LTR 排版"这种查不出来的组合。ICU 消息里的 `{n, number}` 也走同一 locale。

---

## 八、三种宿主形态（验证 API 够用）

**A. 路由带语言（site 就用这种）**：locale 由 URL 段决定，服务端/预渲染时已知，一路以 prop 传下，**零探测、零闪烁**。

**B. SPA（偏好存 localStorage）**：切换语言 → `localeStorage.set()` + 更新 Provider 的 `locale` state + 设置 `<html lang>`。首帧必然默认语言，挂载后一次切换。

**C. 静态站多语言各一套构建**：构建时注入常量，产物里没有切换逻辑。

## 九、边界情况

| 情况 | 处理 |
|---|---|
| `locale` 是日语但内置只有中英 | 宿主给 `messages` 就会用；未给的键回退 `fallbackLocale` |
| `locale="en-US"` 但 `messages` 是中文 | 允许，不校验。`messages` 是显式覆盖，优先级最高 |
| 宿主只翻了 80% 的键 | 剩余回退 `fallbackLocale`，可能混排，属预期 |
| Node small-icu 缺语言数据 | `Intl.PluralRules.supportedLocalesOf(locale)` 为空 → 文案照换，复数退化 `en`，开发模式告警 |
| 嵌套两层 Provider | `locale` 就近覆盖，`messages` 逐键叠加 |
| 语言切换时编辑器正聚焦 | 只重渲染外壳，光标/选区/撤销栈保持（§6.2） |
