## 一、为什么要构建

本包最初直接发布 TS 源码（`main` / `types` 指向 `src/*.ts`）。在 monorepo 里这没问题——Next 的 Turbopack 会自动转译 workspace 包。但**发布到 npm 后不成立**：

| 消费者 | 能否直接读依赖里的 `.ts` | 需要的额外配置 |
|---|---|---|
| Next.js（Turbopack） | 不能 | `transpilePackages: ["@heikeson/md-engine"]` |
| Vite | 能（会转译依赖中的 TS） | 无 |
| tsup / webpack 项目 | 不能 | 各自的 transpile 配置 |

这与「宿主只升版本、无感升级」的目标直接冲突。构建后消费者零配置。

第二个理由：`types` 指向 `.ts` 时，消费者的 TS 会**完整类型检查包内源码**，`skipLibCheck` 管不到 `.ts` 文件，包内任何瑕疵都会在宿主构建时报出来。构建产出 `.d.ts` 后，这些检查收敛到发布前。

## 二、产物结构

```
dist/
├─ index.js            904B   主入口（只做 re-export）
├─ index.d.ts          14KB   含 jsxBlock 节点类型与 token 类型增强
├─ chunk-*.js                 主入口与组件入口共享的实现
├─ components/index.js 247B   组件映射（薄壳）
├─ components/index.d.ts
├─ editor/index.js     18KB   编辑器（含 CodeMirror 调用）
└─ editor/index.d.ts

styles/engine.css      11.6KB  样式（不构建，见第五节）
```

发布白名单（`package.json` 的 `files`）：`dist`、`styles`、`README.md`、`对接契约.md`、`LICENSE`。**源码不发布。**

## 三、三个入口必须隔离

`tsup.config.ts` 里三个 entry 分别产出：

| 入口 | 内容 | 约束 |
|---|---|---|
| `.` | 解析 / 渲染 / 序列化 / 格式化 / registry | **不得引入编辑器代码**，否则阅读页会连带加载 CodeMirror |
| `./editor` | `MarkdownEditor` + CodeMirror 封装 | 仅后台使用 |
| `./components` | 组件映射 | 宿主做单组件覆盖时用 |

构建后自检（已写入验收）：

```bash
Select-String -Path dist/index.js,dist/chunk-*.js -Pattern "codemirror","EditorView"
# 只应命中 editor 相关产物；主入口与共享 chunk 不得出现
```

## 四、依赖一律 external

| 类别 | 处理 | 原因 |
|---|---|---|
| `react` / `react-dom` | external（peer） | 宿主提供，且必须唯一 |
| `@codemirror/*` | external | 两份 state 会导致事务互不认 |
| `lucide-react` | external（dependencies） | 体积大，宿主通常已有 |
| unified / remark-* / rehype-* / mdast-* / micromark-* | external | 两份 processor 会导致插件不生效，且体积翻倍 |

`tsup` 默认会把 `dependencies` 全部 external，配置里再显式兜一层，避免将来加依赖时漏掉。

## 五、样式为什么不构建

`styles/engine.css` 里是 `@apply` 语句，必须在**宿主的 Tailwind 管线**里执行：

- 保留 `@apply` → 颜色、圆角跟随宿主主题变量（`bg-muted`、`text-foreground`），宿主换明暗主题自动适配
- 预编译成纯 CSS → 值写死，主题适配全废

因此 `exports["./styles.css"]` 直接指向 `styles/engine.css`，不作为构建产物。宿主要求：Tailwind 4.x。

## 六、常用命令

```bash
npm run typecheck  # tsc --noEmit，检查源码类型
npm run build      # tsup：产出 dist（含 .d.ts 与 sourcemap）
npm pack --dry-run # 核对发布清单，确认不含源码
```

> 调试不要再绕宿主：本仓库自带 `npm run dev`（Vite playground，5180 端口，直接消费 `src/`）与 `npm run snapshot`（静态快照）。两者只用于开发，不参与发布；详见 [本地开发渲染/需求文档.md](./本地开发渲染/需求文档.md)。

`prepublishOnly` 已串好：**发布时自动先 `build` 再 `typecheck`**，构建失败无法发布。

## 七、发布流程

```bash
# 1. 改版本（语义化）
npm version patch|minor|major --no-git-tag-version

# 2. 构建并核对
npm run build
npm pack --dry-run

# 3. 发布
npm publish
```

版本口径：

| 变更 | 版本 |
|---|---|
| 修 bug、调整样式细节 | patch |
| 新增组件 / 新增可选属性（向后兼容） | minor |
| 破坏性变更 | **不允许**（契约 C1：语法只增不改，已发布组件的名字与属性语义永不修改） |

## 八、构建期踩过的坑

### 8.1 dts 漏掉类型增强（已修）

`src/syntax/jsx-types.ts` 是模块（含 `import type`），它的 `declare module "micromark-util-types"` 只有**被导入时**才生效。主项目靠 `tsconfig.include` 把整个 `src` 纳入编译，检查能过；但 `tsup` 的 dts 从入口沿依赖图分析，会漏掉它，于是报一片：

```
Argument of type '"jsxBlock"' is not assignable to parameter of type 'keyof TokenTypeMap'
```

修法：在 `jsx-flow.ts` 与 `jsx-mdast.ts` 顶部加副作用导入：

```ts
import "./jsx-types";
```

### 8.2 CodeMirror 被打包两份

如果把 `@codemirror/*` 从 external 里去掉，宿主与包各持一份 state，表现为「编辑器能输入但不触发 onChange」或「工具栏命令无效」。这条务必保持 external。

### 8.3 样式不生效

包样式依赖宿主 Tailwind 4。若宿主是 Tailwind 3，`@apply` 里的 `bg-muted` 等语义类不存在，会编译报错。宿主接包前先确认 Tailwind 版本。

## 九、发布前验收

- [ ] `npm run build` 成功，`dist/` 下三个入口齐全
- [ ] 主入口产物**不含** `codemirror` / `EditorView`
- [ ] `dist/index.d.ts` 含 `declare module "mdast"` 与 `TokenTypeMap` 增强
- [ ] `npm pack --dry-run` 清单只含 `dist` / `styles` / 文档 / LICENSE，**不含 `src`**
- [ ] `styles/engine.css` 仍是 `@apply` 源码（未被预编译）
- [ ] `npm run typecheck` 零错误
