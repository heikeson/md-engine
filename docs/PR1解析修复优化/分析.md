## 3. 仍存在的问题

### P0-1 行内标签识别漏判属性里的 `>`

- 现象：`<Tabs>` / `<Tab title="x>y" value="a">A</Tab>` / `</Tabs>` 渲染出**空标题的标签页**（props 全丢）。
- 证据（实测）：
  - 树结构：`root[jsxBlock(Tabs)[paragraph[html,text,html]]]` —— 没有收拢成 `Tab` 块；
  - 渲染：`<button role="tab">` 内为空，`value` 也丢了。
- 原因：`jsx-inline.ts` 自己写了一份 `OPEN_TAG_RE = /^<([A-Za-z][\w]*)([^>]*?)(\/?)>$/`，`[^>]*?` 无法跨过属性值里的 `>`；而 `jsx-mdast.ts` 的 `parseOpenTag` 已经用 `[\s\S]*?` 正确处理了这种情况（`rest=" title=\"x>y\""` 能解析出属性）。
- 影响：静默失效——`roundtrip` 文本看起来没变（原文被原样写回），只有渲染才露馅，最容易被漏掉的那类缺陷。
- 方案：删掉 `jsx-inline.ts` 的 `OPEN_TAG_RE`，改为 `const parsed = parseOpenTag(raw)`，用 `parsed.name`（非空且在白名单内）判定，用 `parsed.selfClosing` 判定自闭合。顺带消掉两处问题：正则重复、名字口径 `[\w]*`（含 `_`/数字）与词法层 `asciiAlphanumeric` 不一致。

### P1-2 行内子项跨段落时完全不收拢

- 现象：子项内容里有空行（多段），例如

  ```md
  <Tabs>
  <Tab value="a">第一段

  第二段</Tab>
  </Tabs>
  ```

  渲染成**两个空标题标签页**，正文被拆到两个面板。
- 原因：`foldParagraph` 只在同一个 `paragraph` 内找闭标签，跨段落即放弃（注释里写明「交给 policy」，但 policy 并不会补 props）。
- 方案（二选一）：
  - 方案 A（推荐）：折叠粒度从「段落内」提升到「父节点子序列」——从段落 i 开始，若开标签未在本段闭合，则继续吃 i+1、i+2… 直到找到闭标签，把中间段落作为子节点；此时 `data.inline` 不置位（按块形态序列化），保证「解析正确、序列化稳定」。
  - 方案 B：文档化限制，README / 对接契约写明「行内写法的子项不能含空行」，解析侧维持现状（props 丢失的风险仍在）。
- 风险：A 需要改 `walk` 的遍历粒度，并把「行内序列化」和「跨段落折叠」两个概念分开（`inline` 只描述序列化形态）。

### P1-3 缩进只对「标签行」生效，正文/代码行仍会走形

- 现象 1：`<Folder>` 内 4 空格缩进的正文 → 变成 ``` 代码块，且 roundtrip 把代码块固化（内容被"改写"成代码）。
- 现象 2：缩进更深时更糟——`<Cards>`（4 空格缩进）内的代码块（8 空格）只把标签行去了缩进，代码行仍是 8 空格，序列化后代码块内容**多出 4 空格**（实测输出 ````` ```\n    const a = 1;\n``` ```）。
- 原因：去缩进只发生在「行首是已知标签」的行，其余行原样进入子文档，于是「相对缩进」被打破。
- 方案：把「标签行去缩进」升级为「容器内容统一去缩进」：
  1. 首行（第一条非空内容行）若是已知标签行，记录其缩进宽度 N（现有 `tokenizeIndentTag` 探测时顺手记下即可）；
  2. 之后每行 `lineStart` 统一剥掉 `min(行首空白, N)`；
  3. N 未确定前（首行不是标签）保持 N=0，即完全维持今天的行为。
- 收益：正文不再变代码块；容器内代码块内容保真；「按层级缩进排版」的写法可以整体工作。
- 风险：语义边界变化，必须同步 README「书写约束」与对接契约，并补 selfcheck 用例（缩进正文、缩进代码块、缩进嵌套两层）。

### P1-4 行内序列化会加多余的转义符

- 现象：`<Tab value="a"># 标题</Tab>` 存回去变成 `<Tab value="a">\# 标题</Tab>`；`- 破折` → `\- 破折`；`1. 列表` → `1\. 列表`。
- 原因：`handleJsxBlock` 走 `state.containerPhrasing(first, info)`，而 `info.before` 为空串 → 序列化器认为正文在「行首」，执行了行首转义。
- 方案：行内分支传 `{ ...info, before: ">", after: "<" }`（正文实际就夹在 `>` 与 `<` 之间）。渲染结果不变，只是不再无端加反斜杠。
- 影响面：仅 `data.inline` 分支，改动 1 行。

### P1-5 行内序列化只取 `children[0]`

- 现状：`const first = node.children[0]`，只处理一个子节点。当前折叠逻辑恰好只产出一个 `paragraph`，所以看不出问题；但一旦 P1-2 采纳方案 A、或外部（编辑器/宿主）手工构造 `data.inline` 节点，就会**静默丢内容**。
- 方案：把子节点拍平成单个 `paragraph` 再交给 `containerPhrasing`：

  ```ts
  const flat = node.children.flatMap((c) => (c.type === "paragraph" ? c.children : [c]));
  const body = flat.length > 0 ? state.containerPhrasing({ type: "paragraph", children: flat }, { ...info, before: ">", after: "<" }) : "";
  ```

### P1-6 折叠出的内层 `paragraph` 复用了外层段落的 position

- 现状：`position: paragraph.position` —— 内层段落的位置区间**包含开闭标签本身**，与真实内容不符。
- 影响：`extractBlocks` / `rehypeSourcePositions`（编辑器滚动同步）拿到的偏移偏大；也给 `promoteBlockMath` 造成误判（`<Tab>$$x$$</Tab>` 里 `source.slice` 出来带标签，于是不会被提升——这个结果恰好可接受，但依据是错的）。
- 方案：用首尾 inner 节点的 position 计算（与现有 `spanPosition` 同一手法），缺失时回退为 `undefined` 而不是照抄外层。
