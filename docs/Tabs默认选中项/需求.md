## 1. 需求由来

提议给 `<Tabs>` 增加容器级属性（如 `defaultValue="pnpm"`）指定默认页签，并让容器对外暴露当前激活项。

## 2. 现状核对

现有实现（`src/components/tabs.tsx`）已具备"默认打开哪个页签"的能力：

| 能力 | 实现位置 | 说明 |
|---|---|---|
| 默认选中项 | `Tab` 子项的布尔属性 `default` | 有 `default` 的子项即为初始激活项 |
| 无 `default` 时 | 同上 | 取第一项 |
| 当前哪一项 | `aria-selected` / `role="tabpanel"` | 标准 WAI-ARIA Tabs 结构，读屏与 CSS 均可用 |
| 键盘切换 | `onKeyDown` | ←/→ 循环，Home/End 首尾 |

## 3. 决策

**不新增容器属性，不改组件实现。**

| 理由 | 说明 |
|---|---|
| 既有语义已覆盖 | `default` 布尔表达的正是"默认打开哪个页签"，再加 `defaultValue` 会出现两套默认项口径 |
| 契约 C1 风险 | 已有文章大量使用 `<Tab value=… default>`；新增并列属性必然要定义优先级，属于给作者增加心智负担 |
| 真实缺口是文档 | 问题不在能力缺失，而在站点没把 `value` / `default` 的语义与边界讲清（多个 `default` 谁生效、不写时打开哪项） |

## 5. 后续（如需再议）

若将来确实需要"容器级指定默认项"（例如同一份内容被多页复用、需按页覆写），再单开需求，届时必须给出与 `default` 的优先级且只能新增、不能改旧语义。
