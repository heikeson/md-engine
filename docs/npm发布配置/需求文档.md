## 一、背景

`@heikeson/md-engine` 是源码直发的 npm 包（`main`/`types`/`exports` 均指向 `src/*.ts`，不做编译产物，依赖宿主构建器消费 TS 源码）。当前 `package.json` 已具备 `name`/`version`/`exports`/`files`/`peerDependencies`/`scripts.typecheck` 等核心字段，但**发布链路缺少以下配置**，直接 `npm publish` 会有问题或不够规范：

| 缺失项 | 影响 |
|---|---|
| `.npmrc` | scope 包默认 private，不显式 `--access public` 会失败；加 `access=public` 兜底 |
| `.npmignore` | 当前 `files` 已限白名单，但 `.npmignore` 缺失会导致 `.git`/`node_modules` 等若被意外打包；双保险 |
| `LICENSE` 文件 | `package.json` 声明 MIT 但无 LICENSE 文件，npm 会警告 |
| `package.json` 元信息 | 缺 `repository`/`author`/`homepage`/`bugs`/`publishConfig`/`engines` |
| 发布脚本 | 缺 `prepublishOnly`（发布前自动 typecheck + dry-run 校验） |

## 二、目标

1. 让 `npm publish --access public` 一次成功，产物只含 `src/` + `README.md` + `对接契约.md` + `LICENSE`。
2. 发布前有自动校验门禁（typecheck + `npm pack --dry-run` 产物清单检查）。
3. npm 页面与 `npm info` 展示完整元信息（仓库、作者、主页、问题反馈）。

## 三、需求清单

### 3.1 新建文件

| 文件 | 内容 | 说明 |
|---|---|---|
| `.npmrc` | `access=public`<br>`registry=https://registry.npmjs.org/` | scope 包默认公开访问，避免漏带 `--access public` |
| `.npmignore` | 排除 `.git`/`node_modules`/`docs`/`*.log`/`.tmp`/`tsconfig.json`/`.codebuddy` 等 | 与 `files` 白名单形成双保险；`docs` 是开发文档不必进包 |
| `LICENSE` | MIT 全文，版权 `Copyright (c) 2026 heikeson` | 与 `package.json` 的 `"license": "MIT"` 一致 |

### 3.2 修改 `package.json`

新增以下字段（不改动现有 `exports`/`files`/`dependencies`/`peerDependencies`）：

```jsonc
{
  // 已有字段不动
  "author": "heikeson",
  "repository": {
    "type": "git",
    "url": "git+https://github.com/heikeson/md-engine.git"
  },
  "homepage": "https://github.com/heikeson/md-engine#readme",
  "bugs": {
    "url": "https://github.com/heikeson/md-engine/issues"
  },
  "publishConfig": {
    "access": "public",
    "registry": "https://registry.npmjs.org/"
  },
  "engines": {
    "node": ">=20"
  },
  "scripts": {
    "typecheck": "tsc --noEmit",           // 已有，保留
    "prepublishOnly": "npm run typecheck && npm pack --dry-run"
    // 说明：prepublishOnly 是 npm publish 前自动钩子，
    //       先 typecheck 再 dry-run 看产物清单，两步过了才真正发布
  }
}
```

### 3.3 不做的事

- **不引入构建步骤**：保持源码直发，不加 `tsup`/`tsc --emitDeclarationOnly`/`dist/`。理由：README 与对接契约已明确"可直接消费 TS 源码"，宿主是 Next/Turbopack/Vite。
- **不写 CHANGELOG**：本项目按语义化版本手动管理，README 已说明版本递增规则。
- **不配 CI**：本次只做本地发布配置，CI 留待后续。
- **不碰 `src/` 任何代码**：纯配置初始化。

## 四、产物清单验证标准

执行 `npm pack --dry-run` 后，输出应**只含**以下条目（含 LICENSE）：

```

npm notice === Tarball Contents ===
npm notice 444.1kB  README.md
npm notice 12.0kB   对接契约.md
npm notice 1.1kB    LICENSE
npm notice <size>   src/index.ts
npm notice ...      src/**/*.ts, *.tsx, *.css
npm notice === ===
```

**禁止出现**：`.git/`、`node_modules/`、`docs/`、`tsconfig.json`、`.npmrc`、`.npmignore`、`.gitignore`、`.codebuddy/`。

## 九、已知漏洞跟踪（2026-10-25 记录）

### `katex` 原型污染（低危）

| 项 | 内容 |
|---|---|
| 漏洞 | [GHSA-238p-pmpm-9mq7](https://github.com/advisories/GHSA-238p-pmpm-9mq7) 原型污染，可绕过信任限制 |
| 影响范围 | `katex@0.11.0 - 0.18.1`，经 `rehype-katex@7.0.1` → `katex`、`remark-math@6.0.0` → `micromark-extension-math` → `katex` 两条传递依赖链引入 |
| 严重程度 | low（低危） |
| npm 建议 | 降级 `rehype-katex@1.2.0`（主版本 7→1，API 不兼容，属 breaking change） |
| 决策 | **暂不处理** |
| 理由 | 1. 低危；2. 本包是 Markdown 渲染引擎，公式输入来自作者文档内容，攻击面有限；3. 降级到 `rehype-katex@1.x` 会破坏 `render.tsx` 调用；4. 等 `katex` 上游发版后 `rehype-katex` 跟进，届时 `npm update` 自动修复 |
| 复查时机 | 下次升级依赖时（`npm update` / `npm audit`），若 `katex` 已发修复版则顺带升级 |

> 用户于 2026-10-25 确认「暂不处理」。执行 `npm publish` 不受阻塞——漏洞在传递依赖里，不影响发布门禁。
