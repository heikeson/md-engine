> @description 为什么 `dev/` playground 的渲染结果与 `blog-heikeson2026` 不完全一致，哪些属预期差异、哪些才是引擎缺陷。

> @updated 2026-10-26 22:07

## 一、结论先行

**大部分差异是预期的**：宿主在引擎之上又叠了一层站点定制（组件覆盖 + 插件注入 + 预处理 + 完整主题），`dev/` 只还原引擎层。

判据只有一条：

| 现象 | 性质 |
|---|---|
| 结构不同：组件没渲染、尖括号/HTML 泄漏、内容顺序变化、文本丢失 | **引擎缺陷**，要修 |
| 表现不同：标题多了锚点与复制按钮、代码块没有高亮、图片下方没有题注、字体与间距不同、表格没有横滑包裹 | **宿主定制**，正常 |

## 二、宿主的完整管线（`components/site/article/markdown-content.tsx`）

```tsx
<MarkdownRenderer
  content={legacyHtmlTablesToGfm(content)}       // ① 预处理
  className="prose-site …"
  config={{
    components: { h1~h4, pre, a, table },        // ② 组件覆盖
    rehypePlugins: [rehypeImageCaption],          // ③ rehype 注入
    remarkPlugins: [remarkLinkTarget],            // ④ remark 注入
  }}
/>
```

| 层 | 宿主做了什么 | `dev/` 有没有 |
|---|---|---|
| ① 预处理 | `legacyHtmlTablesToGfm`：把 TipTap 时代存下的裸 `<table>` HTML 转成 GFM 表格 | ❌ |
| ② `h1~h4` | 换成 `Heading`：左侧 `#` 锚点、整条标题可点、行尾复制链接按钮 | ❌（只有 `rehype-slug` 生成的 id） |
| ② `pre` | 换成 `CodeBlock`：shiki 高亮、mermaid 渲染、按后台设置切换代码块风格 | ❌（纯 `<pre>`） |
| ② `a` | 命中配置或 `target="_blank"` 时加 `rel="noopener"` | ❌ |
| ② `table` | 外层包 `overflow-x-auto`（窄屏横滑） | ❌ |
| ③ `rehypeImageCaption` | 给图片生成题注结构 | ❌ |
| ④ `remarkLinkTarget` | 解析 `[文字](url){target="_blank"}` 后缀 | ❌ |
| 样式 | `theme.css` 全套语义令牌 + `prose.css` / `heading.css` / `prose-code.css` | 只有 7 个色值的近似令牌 + 20 行近似排版 |

## 三、逐项对照

| 你会看到 | 原因 | 是否正常 |
|---|---|---|
| 标题旁没有 `#`，也没有复制链接按钮 | 宿主覆盖了 `h1~h4` | ✅ 正常 |
| 代码块没有颜色、也没有标题栏 | shiki 在宿主侧；引擎只输出 `data-code-*` 属性 | ✅ 正常 |
| mermaid 图不渲染 | 同上 | ✅ 正常 |
| 图片下方没有题注 | 宿主插件 `rehypeImageCaption` | ✅ 正常 |
| 字体、字号、行距、留白不同 | `dev/theme.css` 用近似值；宿主有自己的 prose 排版 | ✅ 正常 |
| 颜色（尤其 muted）略有差别 | 令牌取值按宿主近似，未逐像素对齐 | ✅ 正常 |
| 宽表格不出横向滚动 | 宿主用 `overflow-x-auto` 包裹 | ✅ 正常 |
| 外链不在新标签页打开 | 宿主 `a` 覆盖 | ✅ 正常 |

**引擎层必须一致的部分**（这几项不一致就是 bug）：

- 容器（Callout / Tabs / Steps / Cards / Accordion / Files / TypeTable / Image）的 DOM 结构与语义类名
- 组件内部交互（Tabs 切页、Accordion 展开、Image 灯箱放大）
- 诊断（未闭合 / 超深嵌套 / 非法协议）与降级结果
- 公式（KaTeX 结构）、表格（GFM 语义）、代码块 `data-code-*` 属性

## 四、如何快速判定

1. **看结构，不看样式**：`<Callout>` 是否变成 `.callout` 结构？内容是丢了还是只是变小了？
2. **对照宿主实际调用**：宿主若有覆盖，本地不覆盖导致的表现差异一律按预期处理。
3. **对同一段 Markdown 两边跑**：结构不一致 → 报引擎缺陷；结构一致、观感不同 → 属宿主定制。

## 五、可选增强（未做，按需再提）

| 想法 | 说明 | 成本 |
|---|---|---|
| 在 `dev/` 里复刻宿主的组件覆盖 | 能 1:1 看到宿主效果，但要把 shiki 等依赖搬进本仓库 | 中，且违背"引擎仓库不带宿主定制"的边界 |
| 只复刻轻量项（标题锚点、表格横滑） | 有限收益，容易与宿主实现漂移 | 低 |
| 保持现状 + 本文档做判定依据 | 引擎层验证靠本地，站点观感靠宿主 | 已采用 |

> 结论：`dev/` 的定位是**引擎层验证台**，不是宿主预览器。需要看站点真实效果时，仍以宿主为准。
