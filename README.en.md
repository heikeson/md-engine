# @heikeson/md-engine

[简体中文](./README.md) | English

A Markdown renderer for React, plus an editor built on CodeMirror 6. GFM and math are supported.
The interesting part is this:

```md
<Callout type="tip" title="Heads up">
  The body is still Markdown — `inline code` and [links](https://example.com) work as usual.
</Callout>
```

These angle-bracket containers are not scraped out of the rendered HTML with a regex; they land in
the mdast just like headings and lists. They therefore carry position info, can be serialized back
to the source, and can be swapped for your own component as a whole block. Run `md → AST → md` and
the text comes back byte for byte.

## Install

```bash
npm install @heikeson/md-engine
```

Requires React 19 or later. The package ships ESM only; older Jest or webpack 4 setups need their
own interop layer. Styles are plain CSS and have nothing to do with Tailwind — they render fine even
if the host defines no theme variables.

## Rendering

```tsx
import { MarkdownRenderer } from "@heikeson/md-engine";
import "@heikeson/md-engine/styles.css";

export default function Article({ content }: { content: string }) {
  return <MarkdownRenderer content={content} className="prose-site" />;
}
```

Do not drop `prose-site` — the styles for all eleven containers hang off it. Mermaid uses
`.lkes-mermaid` and the editor uses `.md-editor`, neither of which you need here.

Parsing and rendering never touch `window` or `document`, so the server can call them directly.

## Containers

| Container | Props | Children |
| --- | --- | --- |
| `Callout` | `type` (`note` `info` `tip` `important` `warning` `caution` `danger`, default `note`), `title`, `icon` | body |
| `Tabs` | none | `Tab`: `value`, `default` |
| `Steps` | none | `Step`: `title` |
| `Cards` | none | `Card`: `title`, `href`, `icon`, `description` |
| `Accordion` | none | `AccItem`: `title`, `type` (`open` / `close`) |
| `Files` | none | `Folder`: `name`, `defaultOpen`; `File`: `name`, `href`, `icon` |
| `TypeTable` | none | `TypeItem`: `name`, `type`, `default`, `required` |
| `Columns` | none | `Column`: `width` |
| `Timeline` | none | `TimelineItem`: `date`, `title`, `type` |
| `Video` | `src`, `poster`, `caption`, `width` | self-closing |
| `Image` | `src`, `alt`, `align`, `width`, `caption`, `zoom` | self-closing |
| `Mermaid` | `title`, `height` | raw text, not parsed as Markdown |
| `div` | `class`, `id` | body; attributes pass through to the DOM |

```md
<Tabs>
  <Tab value="npm">npm install @heikeson/md-engine</Tab>
  <Tab value="pnpm">pnpm add @heikeson/md-engine</Tab>
</Tabs>

<Cards>
  <Card title="Quick start" description="Smallest example that renders a section" href="/docs/start" />
</Cards>
```

A few hard rules — break them and you get no error, just mangled output:

- Containers must start at column 0. Children may be indented, but body lines indented to 4 spaces
  are treated as a code block by CommonMark.
- Only `a="b"` attributes and bare booleans are understood; `{...}` expressions are not supported.
- Tags outside the whitelist are shown as literal text, contents included. If you want a plain block
  you can hang a `class` on, use `div`.
- `Image`, `Video`, `Card` and `File` may self-close; every other container needs a closing tag.
- Nesting stops at 3 levels; anything deeper is emitted as raw text.

## Parsing and serialization

```ts
import { parse, serialize, roundtrip, normalizeMarkdown, diagnose } from "@heikeson/md-engine";

const { tree, blocks, diagnostics } = parse(md);
serialize(tree);          // back to Markdown, preserving shape and blank lines
roundtrip(md);            // shorthand for the two lines above
normalizeMarkdown(md);    // when you want unified formatting; serialize does not reformat for you
diagnose(md);             // diagnostics only, same as parse(md, { blocks: false }).diagnostics
```

`blocks` is a flat block index carrying document-wide offsets — handy for tables of contents,
jumping to a location, and scroll sync. When the editor only needs diagnostics, call `diagnose()` and
skip the full tree conversion.

## Editor

```tsx
"use client";

import { useState } from "react";
import { MarkdownEditor } from "@heikeson/md-engine/editor";
import "@heikeson/md-engine/styles.css";

export default function EditorPage() {
  const [value, setValue] = useState("");
  return (
    <MarkdownEditor
      value={value}
      onChange={setValue}
      view="split"
      config={{ placeholder: "Start writing…" }}
    />
  );
}
```

It is a controlled component: `value` is the Markdown text, editing on the left and previewing on the
right. The snippets the toolbar inserts are generated by `registry.ts`, sharing names and props with
the parsing rules, so they cannot drift apart. Shortcuts go through the same implementation as the
buttons: `Mod+B`, `Mod+I` and `Mod+E` for bold, italic and inline code, `Mod+Shift+S` for strikethrough,
`Mod+1` for a level-2 heading, `Mod+Shift+Q` for a quote, `Mod+Shift+L` for a list.

## Diagrams

`<Mermaid>` renders source code only by default. To draw actual diagrams on the page, merge the
overrides inside a client component:

```tsx
"use client";
import { MarkdownRenderer, mdxComponents } from "@heikeson/md-engine";
import { mermaidComponents } from "@heikeson/md-engine/mermaid";

const components = { ...mdxComponents, ...mermaidComponents };

<MarkdownRenderer content={md} config={{ components }} />;
```

The key is `Mermaid`, capitalized. Lowercase raises no error — the diagram just stays as source.
`mermaid` is an optional peer; without it, rendering degrades to source code and parsing/serialization
are unaffected.

## Locales

Built-in `zh-CN` and `en-US`. Pick a locale bundle with `config.locale`, or override individual strings
with `config.messages`. To set it once at the root, wrap the app in a Provider:

```tsx
import { MdEngineProvider } from "@heikeson/md-engine";

<MdEngineProvider locale={locale}>
  <App />
</MdEngineProvider>
```

`locale` must be a controlled value that matches on server and client — usually taken from a URL
segment or a request header. The library does not read `navigator`, cookies or `<html lang>`, because
those make the first paint disagree with the server under SSR. If you really need client-side
detection, call `detectLocale()` inside an effect.

## Swapping components

```tsx
<MarkdownRenderer
  content={md}
  config={{
    components: { Callout: MyCallout }, // replace just this one, everything else uses the built-in
    remarkPlugins: [],
    rehypePlugins: [],                  // must be synchronous, otherwise SSR is unsafe
    sourcePositions: false,             // only needed for editor scroll sync
  }}
/>
```

Inside your own components, read strings with `useUIText()` and format with `useMessage()` using ICU
syntax.

## Styles

Import `@heikeson/md-engine/styles.css` once. Colors come from standalone `--lkes-*` variables: nine
tokens with light and dark literals. Add `.dark` or `[data-theme="dark"]` on an ancestor to switch the
whole thing to dark. The token list and override recipes are in section 10 of
[the integration contract](./对接契约.en.md).

Importing per component also works — `styles/*.css` is published as-is in the npm package. But the
tokens live in `tokens.css` alone: import only a slice and you get no `--lkes-*`, so dark mode stops
working and colors fall back to hardcoded values. Order matters too — `tokens` first, so the
`components` layer can win over the token layer:

```ts
import "@heikeson/md-engine/styles/tokens.css";
import "@heikeson/md-engine/styles/callout.css";
```

## Development

```bash
npm run dev        # playground for renderer + editor work
npm run snapshot   # static snapshot with roundtrip and diagnostics self-checks
npm run selfcheck  # parse, render and serialize assertions against the build
npm run typecheck  # tsc --noEmit
npm run build      # dist and dist/styles.css
```

`dev/`, `docs/` and `site/` are not published; `files` ships only `dist`, `styles`, the READMEs,
`对接契约.md`, `对接契约.en.md` and `LICENSE`.

```
src/
├─ registry.ts      syntax declarations, the single source of truth
├─ policy.ts        depth trimming, unclosed detection, diagnostics
├─ parse.ts / blocks.ts
├─ render.tsx / serialize.ts / format.ts
├─ syntax/          micromark angle-bracket extension
├─ components/      container components and mapping
├─ mermaid/         the /mermaid entry
├─ editor/          CodeMirror wrapper, toolbar, scroll sync
└─ locales/         locale bundles
styles/             plain CSS slices
```

## Compatibility

Shipped API stays put: component names, prop names and semantics only grow, new config options must
carry a default, and style class names and variables are supplied by the package. Anything else is a
breaking change and needs a major version.
