## 一、已修复（前两轮报告为缺陷的用例）

| 用例 | 修复前 | 现在 |
|---|---|---|
| 围栏（```）里写 `</Callout>` | `[code:"", ]` + 兄弟 `code` → 内容丢失 | `[code:"</Callout>"]`，往返逐字一致 |
| `~~~` 围栏里写 `</Callout>` | 同上，且围栏被自己立刻收尾 | `[code:"</Callout>"]`（围栏字符按 GFM 规范化为 ``` ） |
| 围栏里写同名 `<Callout>` | 嵌套计数被污染，外层等不到闭合 | `[code:"<Callout>\n</Callout>"]`，逐字一致 |
| `Tab` 内围栏里写 `</Tab>` | 子项被截断 | `code:"</Tab>"`，逐字一致 |
| 行内子项属性含 `>` | `Tabs:0`，props 全丢 | `Tab{value=a,title=x>y}`，`Tabs:1` |
| 行内子项含空行（Tabs / TypeTable） | `Tabs:0` / `TypeTable:0`，内容碎成两段 | 单个子项、两个段落 |
| 行内子项已被多余转义 | `\# 标题`、`1\. 列表` | 原样 `# 标题`、`1. 列表` |
| 紧凑写法 / 带空行写法 / 嵌套容器 | 保存时被强行展开成「开标签行 + 空行 + 内容 + 空行 + 闭标签行」 | 按原文形态逐字写回 |
| 空容器 `<X>\n</X>` | 存回变成 `<X></X>`，再解析不再是容器 | 保持开闭标签各占一行 |
